# Library Tests: TypeScript `conformance` runner, jsx / jsdoc / salsa / typings (#1282)

Part of [library-tests-typescript.md](library-tests-typescript.md); the oracle, baseline IO, control and ratchet are those of [library-tests-typescript-compiler.md](library-tests-typescript-compiler.md), and the `conformance` wiring is that of [library-tests-typescript-conformance-classes-decorators.md](library-tests-typescript-conformance-classes-decorators.md).

**What it is**: `TS_SRC_DIR=<built TypeScript v6.0.3 checkout> uv run python scripts/run-ts-conformance-1282-oracle.py [--dirs d1,d2] [--check-partition] [slice ...] [-- oracle options]` runs the `conformance` runner (`tests/cases/conformance/**`) for the directories `jsx` (232 suites, 1392 tests), `jsdoc` (397, 2382), `salsa` (193, 1158) and `typings` (9, 54), 831 suites and 4986 tests in all (the passing counts `ts-suite/oracle.json` pins per top-level directory), on Node and `jsse --node`. It compares the outcome and error message of every test and every file under `tests/baselines/local` between the engines, re-runs up to seven suites of each directory against corrupted reference baselines (the control), and applies the known-failure ratchet. Skips without `TS_SRC_DIR` (the wrapper always passes `--require`, so it fails instead).

**Wiring**: the script loads `scripts/run-ts-conformance-oracle.py` (#1276, which in turn drives `scripts/run-ts-compiler-oracle.py`) and swaps in the slice module `scripts/ts_conformance_slices_1282.py` (rows `jsx`, `jsdoc`, `salsa`, `typings` and `issue1282`, the four; the `dir:` term and the compiler terms `first:N`, `prefix:`, `shard:I/N`, `files:`, `match:` are those of `ts_conformance_slices.py`) and the known-failures file `ts-suite/conformance-1282-known-failures.txt` (`full test title<TAB>issue`, filed under the tracker #1418; `--record` rewrites it; a listed test that passes fails the run). No shared script or file was edited. Positional slices before `--` run as one oracle run; with none, the four directories run one after the other (`--dirs` picks some), each its own oracle run so a crashed or interrupted one loses nothing, and each wall time is printed. `--check-partition` (Node only; `tests/node_ts_conformance_1282.rs`, `scripts/test_ts_conformance_slices_1282.py`) fails unless the four directories select disjoint suites that add up to `issue1282`.

**Measured** (jsse built from 0b7507cc with `CARGO_PROFILE_RELEASE_LTO=off CARGO_PROFILE_RELEASE_CODEGEN_UNITS=16`, `--jobs 4 --verbose --test-timeout 1800000 --timeout 7200`, 40 suites per batch, a shared 24-core host at load average 10 to 25; command `scripts/run-ts-conformance-1282-oracle.py --dirs typings,salsa,jsx,jsdoc -- ...`):

| directory | tests | Node | jsse | Node process time | jsse process time | wall time |
|---|---|---|---|---|---|---|
| typings | 54 | 54 pass | 54 pass | 3 s | 123 s | 125 s |
| salsa | 1158 | 1158 pass | 1158 pass | 16 s | 693 s | 274 s |
| jsx | 1392 | 1392 pass | 1392 pass | 41 s | 1489 s | 587 s |
| jsdoc | 2382 | 2382 pass | 2382 pass | 30 s | 1331 s | 410 s |
| total | 4986 | 4986 pass, 0 fail | 4986 pass, 0 fail | 90 s | 3636 s | 1396 s |

Per-test outcomes agree and no test fails on either engine. The corrupted-reference control (the six suites of `typings` and seven of each other directory, with references appended to, replaced, removed, or added for a baseline the test does not produce) fails the same tests with the same messages on both engines and writes identical local baselines, and those are the only files under `tests/baselines/local`. So no engine or host change was needed and `ts-suite/conformance-1282-known-failures.txt` is empty. A regression shows up as a test passing on Node and failing on jsse, which the oracle reports until it is fixed or filed under #1418 and listed in that file.
