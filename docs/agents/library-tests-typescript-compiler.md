# Library Tests: TypeScript `compiler` runner oracle

Split from [library-tests-typescript.md](library-tests-typescript.md) to keep each file under the 20,000-byte budget.

**What it is** (#1268): `TS_SRC_DIR=<built TypeScript v6.0.3 checkout> uv run python scripts/run-ts-compiler-oracle.py [--jobs N (at most 4)] [--batch-size N] [--test-timeout MS] [--no-control] [--record] [--verbose] [--list] [slice ...]` runs a slice of the `compiler` runner (`tests/cases/compiler`, 7276 suites of 6 tests = the 43656 tests of `ts-suite/oracle.json`) through mocha and `built/local/run.js` on Node and `jsse --node` and compares them test by test. Skips without `TS_SRC_DIR` (`--require` makes that an error). Helpers: `scripts/ts_compiler_slices.py`, `ts_compiler_report.py`, `ts_compiler_control.py`. Design: `docs/adr/2026-10-28-1900-node-host-compiler-runner.md`; guards: `tests/node_ts_compiler.rs`, `scripts/test_run_ts_compiler_oracle.py`.

**Baseline IO.** Each run gets a private working directory of symlinks into the checkout (never written to) with its own empty `tests/baselines/local`; `tests/baselines/reference` is the checkout's. A test passes iff its baselines (errors, module-resolution trace, sourcemap record, JS, sourcemap, types and symbols) equal the reference; a mismatch writes the actual text under `tests/baselines/local` (or an empty `<name>.delete` when a reference exists for a baseline the test no longer produces) and fails with `New baseline created at tests/baselines/local/<name>`. So on Node, which passes all 43656, the local directory stays empty.

**Compared** between the engines: the outcome of every test; for a test failing on both, the error message; every file under `tests/baselines/local` byte for byte (each must differ from its reference). A test passing on Node and failing on jsse must be listed in `ts-suite/compiler-known-failures.txt` (`full test title<TAB>issue`; `--record` rewrites the entries of the slice); a listed test that passes fails the run (ratchet); a Node failure, a test not run, or a Node passing count differing from `ts-suite/oracle.json` (for `prefix:` slices) fails the run.

**Control.** Unless `--no-control`, up to seven suites of the slice re-run against a corrupted private copy of their reference baselines (appended to, replaced, removed, or a reference added for a baseline the test does not produce): Node and jsse must fail the same tests with the same messages and write the same local files. This is the check of the diff and baseline-writing path, which the real slice never exercises when everything passes.

**Slices** (`scripts/ts_compiler_slices.py`, positional arguments, a '+' union): `first:N`, `prefix:0-9,A-C` (first character of the file name, case-insensitive; the buckets of `oracle.json`), `shard:I/N` (the runner's `--shards` rule), `files:a.ts,b.ts`, `match:REGEX` (takes the rest of the spec, so it comes last in a union), or a row of `SLICES` (`first200`, `0-9`, `a-c`). Add a row there, or a module of your own with `--slices-module NAME` (a `SLICES` dict importable from `scripts/`), for the #1269-#1273 ranges; the oracle itself needs no edit. `--list` prints the suites of a slice.

**Cost.** Suites are cut into batches (`--batch-size`, default 40) and each batch is one mocha process per engine, at most 4 processes at once over both engines: the 13 MB runner bundle takes about 80 s to load on jsse and the first `Program` (lib.d.ts) 25 to 75 s, so batch many suites per process; `--test-timeout` (mocha `-t`) defaults to 600000 ms. A jsse process of 50 suites takes 2 to 4.5 minutes and about 1.6 GB.

**Measured** (first 200 suites, 1200 tests, 4 batches of 50 plus the control, 4 jobs, `CARGO_PROFILE_RELEASE_LTO=off` build): Node 1200/1200 passing in 13 s of process time, jsse 1200/1200 passing in 570 to 690 s of process time over three runs (about 4.5 minutes of wall time); control: 7 corrupted suites fail identically on both engines with identical local baselines. The known-failure list is empty.
