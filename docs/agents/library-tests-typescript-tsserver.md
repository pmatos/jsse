# Library Tests: TypeScript tsserver unit tests

Split from [library-tests-typescript.md](library-tests-typescript.md) to keep each file under the 20,000-byte budget.

- **TypeScript unit tests: tsserver, files a-m** (#1266): `TS_SRC_DIR=<built TypeScript v6.0.3 checkout> uv run python scripts/run-ts-unittests-tsserver-oracle.py [--half a-m|n-z|all] [--jobs N (at most 4)] [--verbose] [--record] [group ...]` is the #1260 oracle (same options and per-title comparison) over `scripts/ts_unittest_tsserver_groups.py`. The table lists every file of `src/testRunner/unittests/tsserver` (76 files, 1240 tests, the `tsserver` suite of `ts-suite/oracle.json`) with the title prefix of its describes, assigns each to a half by the first letter of its name (`events/*` is `e`) and packs the files of a half into groups, one jsse process per group (27 groups: 15 for a-m, 12 for n-z). `--half` (default `a-m`) picks what a bare run executes; naming groups runs them whatever their half. The baseline `ts-suite/unittests-tsserver.json` holds the counts of all 27 groups (a-m recorded from both engines, n-z from Node's listing until #1267 runs them on jsse) and `known_failures` (empty); the pinned 1240 is checked on bare runs against this run plus the baseline counts of the groups left out. A run with `TS_SRC_DIR` first checks the table against the checkout (a file or top-level `describe` no group selects, or two groups select, fails it). All 421 tests of a-m (applyChangesToOpenFiles, autoImportProvider, compileOnSave 37, configuredProjects 43, declarationFileMaps 21, events 76, externalProjects 24, forceConsistentCasingInFileNames 44, jsdocTag 16, ...) pass on both engines in about 3 minutes at 4 jobs (a jsse process takes 45 to 90 s, mostly loading the runner bundle; the per-test mocha timeout is 600 s). Guards: `tests/node_ts_unittests_tsserver.rs`, `scripts/test_run_ts_unittests_tsserver_oracle.py`.
