# Library Tests: TypeScript `fourslash` runner oracle

Split from [library-tests-typescript.md](library-tests-typescript.md) to keep each file under the 20,000-byte budget.

**What it is** (#1288): `TS_SRC_DIR=<built TypeScript v6.0.3 checkout> uv run python scripts/run-ts-fourslash-oracle.py [--runner fourslash|fourslash-server] [--jobs N (at most 4)] [--batch-size N] [--test-timeout MS] [--no-control] [--record] [--verbose] [--list] [slice ...]` runs a slice of TypeScript's language-service tests through mocha and `built/local/run.js` on Node and `jsse --node` and compares them test by test. The `fourslash` runner is `tests/cases/fourslash/*.ts` (6322 tests, one per file; the `fourslash-server` runner is `tests/cases/fourslash/server/*.ts`, 244 files of 2 tests, driving tsserver, #1293), each parsed (markers, ranges, files), run against an in-process language service through `verify.*`/`edit.*`/`goTo.*` and compared with the baselines of `tests/baselines/reference` (quick info, references, definitions, inlay hints, tsserver logs). Skips without `TS_SRC_DIR` (`--require` makes that an error). Design: `docs/adr/2026-10-29-0100-node-host-fourslash-runner.md`; guards: `tests/node_ts_fourslash.rs`, `scripts/test_run_ts_fourslash_oracle.py`.

**Machinery.** It is the compiler oracle's ([library-tests-typescript-compiler.md](library-tests-typescript-compiler.md)): `scripts/run-ts-fourslash-oracle.py` imports `prepare`, `mocha_run` and `pinned_expected` from `run-ts-compiler-oracle.py` and the comparison, ratchet and known-failure IO of `ts_compiler_report.py`; what differs is in `scripts/ts_fourslash_slices.py` (the test files of a runner, the slice table, the mocha `--grep` of a batch) and `scripts/ts_fourslash_control.py`. Each run has a private working directory of symlinks into the checkout (never written to) with its own empty `tests/baselines/local`, so the baselines a run writes are the run's own.

**Compared** between the engines: the outcome of every test; the error message of a test failing on both; every file under `tests/baselines/local` byte for byte. A test passing on Node and failing on jsse must be listed in `ts-suite/fourslash-known-failures.txt` (`full test title<TAB>issue`; `--record` rewrites the entries of the slice); a listed test that passes fails the run (ratchet); a Node failure, a test not run, or a Node passing count differing from `ts-suite/oracle.json` (for `prefix:` slices) fails the run.

**Control.** Unless `--no-control`, five tests re-run against corrupted input: three whose reference baseline (`<test>.baseline*` or the tsserver log) is appended to, rewritten or removed, and two whose private copy of the test file gets `verify.numberOfErrorsInCurrentFile(12345)` or `verify.currentFileContentIs("corrupted")` appended. Node and jsse must fail the same five with the same messages and write the same local files (the checkout stays untouched: the files live in a private `tests/cases` and reference directory).

**Slices** (positional arguments, a '+' union; terms as in the compiler oracle: `first:N`, `prefix:A-C`, `shard:I/N`, `files:a.ts`, `match:REGEX`, or a row of `SLICES`): the table in `scripts/ts_fourslash_slices.py` already holds the rows of the follow-up issues, `first200` (#1288), `a-c` (#1289, digits included), `d-g` (#1290), `h-m` (#1291), `n-r` (#1292), `s-z` (#1293), `all`; another range is a new row (or a module of your own with `--slices-module NAME`), not a change to the oracle. A bare `--runner fourslash-server` run takes the same rows over the `server` directory.

**Cost.** Batches (`--batch-size`, default 100 tests) are one mocha process per engine, at most 4 processes at once over both engines. A test is cheap once the process is up (the lib files are cached): the first 200 tests took 70 s and 125 s of jsse process time for the two batches, Node 3 s each; jsse peaks near 1 GB per process.

**Engine note.** `merge_sort_by` compares `cmp(later, earlier)` like V8 (the harness sorts with a comparator that answers 1 for equal keys); see the ADR.

**Measured** (first 200 tests, `CARGO_PROFILE_RELEASE_LTO=off`, 4 jobs): Node 200/200 passing, jsse 200/200 passing, 196 s of jsse process time; control: 5 of 5 fail identically on both engines. The known-failure list is empty.

**Slice n-r** (#1292, `prefix:N-R`, 1361 tests, the count `ts-suite/oracle.json` pins): `TS_SRC_DIR=<checkout> uv run python scripts/run-ts-fourslash-oracle.py --known ts-suite/fourslash-known-failures-n-r.txt n-r`. Node 1361/1361 passing in 32 s, jsse 1361/1361 passing in 729 s of process time (14 batches of 100 on 4 jobs, `CARGO_PROFILE_RELEASE_LTO=off` build, shared 24-core host: about 4 minutes wall including the control); every local baseline byte-identical; control 5 of 5 fail identically. No engine or host change was needed and `ts-suite/fourslash-known-failures-n-r.txt` has no entries; a regression shows up as a test passing on Node and failing on jsse, which the oracle reports until it is fixed or filed under #1418 and listed there.
