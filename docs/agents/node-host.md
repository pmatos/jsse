# Node host mode (`--node`): architecture

Read this before touching `node-lib/`, `scripts/node-*.js` or `src/interpreter/builtins/node_host*.rs`. Epic #1214 (run TypeScript 6.0.3's `tsc` and its test suite on jsse) built this layer; the design record is [`docs/adr/2026-10-26-0854-node-host-mode.md`](../adr/2026-10-26-0854-node-host-mode.md) and the per-topic ADRs listed below. Companion pages: [adding a core module](node-host-add-module.md), [running tsc and the TypeScript suite](typescript-suite-local.md), [triage rules](typescript-suite-triage.md).

## The rule that matters most

`--node` is strictly opt-in. Without it no Node global exists and test262 sees the ECMAScript default environment, which is what the pass-list baseline measures. `--prelude` (the test262 runner's flag) never enables it. Three guards pin this: the unit test `host_globals_absent_when_floor_off` (`src/interpreter/tests.rs`), `tests/node_prelude.rs` (the prelude is absent without `--node`, plain and with `--prelude`) and the test262 baseline itself. Several oracle scripts (prelude, event loop) also check their surface is absent without the flag. A change that makes any of it visible by default is a bug, however convenient.

## Layers

| layer | where | what it does |
| --- | --- | --- |
| launcher | `src/cli.rs`, `src/cli_node.rs` | parses `--node` (and `--expose-internals`), splits script arguments verbatim like Node, decides whether the main file is CommonJS, an ES module or `-e`/REPL (`NodeMainKind`, handed to the prelude as `__host_main_kind()`) |
| floor | `src/interpreter/builtins/node_host*.rs` | native `__host_*` primitives for what JavaScript cannot do: syscalls, entropy, clock, exit, process/vm/zlib/wasm contexts, the event-loop queue. Installed by `Interpreter::enable_node_host`; non-enumerable, configurable, captured by the prelude and then deleted |
| prelude | `scripts/node-*.js`, ordered in `src/interpreter/builtins/node_prelude.rs` (`NODE_PRELUDE`) | JavaScript built on the floor: `process`, `console`, `Buffer`, `util`, timers and event loop, the `fs` scripts, WebAssembly, and last `node-builtin-loader.js`. `include_str!`d into the binary and run as global scripts by `load_node_prelude`; nothing is parsed without `--node` |
| builtin modules | `node-lib/<id>.js`, table in `node_host_builtins.rs` (`builtin!("<id>")`) | `require('path')`, `fs`, `events`, `stream`, `child_process`, `vm`, `zlib`, ... in the shape of Node's own `lib/`, evaluated lazily on first `require` by the loader. Ids starting `internal/` are reachable only from other builtins (or with `--expose-internals`) |
| loaders | `node-lib/internal/modules/{cjs,esm}/`, `src/interpreter/builtins/node_host_esm.rs`, `node_host_cjs_lexer.rs` | the CommonJS loader (a script file is the main module), the ES module loader, CJS/ESM interop (named exports found by the CJS lexer), the `module` builtin |

Everything is versioned with the binary: there is no on-disk lookup, so no version skew between the prelude, `node-lib/` and the Rust floor.

## Conventions that bite

- **Prelude order is load order.** The process shim extends the object the console/util shim creates; the timers shim needs the event-loop shim; the fs scripts need `Buffer` and `util`; `node-builtin-loader.js` runs last before `hide-globals`. Adding a prelude script means a new `NODE_PRELUDE` entry in the right place. Most work needs no prelude script, only a builtin module.
- **A floor primitive is a deliberate addition.** Add one only when JavaScript cannot do the job. Take it private in `node-builtin-loader.js` (it captures the global, deletes it and seeds the object as the builtin `internal/host/<name>`, which only builtin modules can `require`) so user code never sees it.
- **Lazy globals.** Web globals (`Event`, `EventTarget`, `AbortController`, `DOMException`, `performance`, ...) come from the `LAZY_GLOBALS` table in the loader (an accessor that loads the module on first touch). A new one is one line.
- **Exit status** precedence: `pending_exit` (`process.exit`, step budget 124) over an uncaught throw (1) over `process.exitCode` over 0. Parse errors keep status 2 (Node uses 1).
- **Tail calls are ordinary calls under `--node`** (V8 has none; mocha's traces need the test's own frame): `Interpreter::tco_on`.
- **`process.env` is a JS-owned snapshot**; the OS environment is never mutated. Native readers (`TZ`) see the startup values.
- **Engine behaviour must match in both execution engines.** The tree-walker (`--no-bytecode`) and the bytecode VM share the host layer; several guards under `tests/node_*.rs` run both (`--no-bytecode`) where the difference is observable, such as stack and async frames.
- **File budget.** Each authored file stays under 20,000 bytes (a hook enforces it; an oversized file may not grow). That is why `internal/path/win32` is two files and why ADRs are split per topic. Put new code and notes in new sibling files.
- **`scripts/node-fs-module.js` is unrelated**: it is the library harnesses' virtual `fs`.

## Verifying behaviour against Node

Authority order is the ECMAScript spec, test262, then node. For host behaviour Node is the oracle: each area has a script `scripts/run-node-<area>-oracle.sh` (path, cjs, esm, events, fs, stream, buffer, child-process, vm, url, os, zlib, ...) that runs `scripts/<area>-fixtures/` on `jsse --node` and Node and diffs stdout and exit status, and a Rust guard `tests/node_<area>.rs` that pins the digest or the output. `./scripts/run-node-prelude-oracle.sh` is the smallest, and the template for a new area. The inventory with options is in [library-tests.md](library-tests.md); for the TypeScript tooling see [library-tests-typescript.md](library-tests-typescript.md).
