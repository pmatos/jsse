# Library Tests: TypeScript `conformance` runner, `expressions` (#1275)

Part of [library-tests-typescript.md](library-tests-typescript.md); the oracle, baseline IO, control and ratchet are those of [library-tests-typescript-compiler.md](library-tests-typescript-compiler.md).

**What it is**: `TS_SRC_DIR=<built TypeScript v6.0.3 checkout> uv run python scripts/run-ts-conformance-expressions-oracle.py [--chunks ex1,ex2,ex3,ex4] [--check-partition] [-- oracle options]` runs the `conformance` runner (`tests/cases/conformance/expressions`: 429 suites of 6 tests = the 2574 tests of `ts-suite/oracle.json`) through mocha and `built/local/run.js` on Node and `jsse --node` and compares them test by test, plus every file under `tests/baselines/local`. `scripts/run-ts-compiler-oracle.py` only knew the compiler runner (its `test.config`, suite titles and slice parser); the wrapper loads that module and points it at `conformance` (`runners: ["conformance"]`, suite titles `conformance tests conformance tests for tests/cases/conformance/<dir>/<file>.ts[ (@config)]`, the `expressions` count read from `oracle.json`) with `scripts/ts_conformance_slices_1275.py`, so other conformance directories need only a `dir:` slice row or a module of their own. `dir:expressions/typeGuards,...` selects suites by directory, `first:N`, `shard:I/N`, `files:` and `match:` work as for the compiler runner (`prefix:` is rejected: conformance file names do not partition by letter).

**Chunks**: the 26 subdirectories are cut into `ex1` (arrayLiterals..the conditional-operator directory, 108 suites), `ex2` (contextualTyping..nullishCoalescingOperator, 91), `ex3` (objectLiterals..typeAssertions, 83) and `ex4` (typeGuards..valuesAndReferences, 147), run one after the other so a crashed chunk does not lose the others; `--check-partition` (Node only; `tests/node_ts_conformance_expressions.rs`, `scripts/test_ts_conformance_slices_1275.py`) fails unless they cover `expressions` exactly once. Known failures: `ts-suite/conformance-expressions-known-failures.txt` (empty).

**Measured** (jsse built with `CARGO_PROFILE_RELEASE_LTO=off`, `--jobs 4`, default batch size 40, a shared 24-core host): Node 2574/2574 passing (648 + 546 + 498 + 882; 77 s of process time), jsse 2574/2574 passing (4063 s of process time: ex1 980, ex2 1076, ex3 1074, ex4 933), about 28 minutes of wall time for all four chunks (404, 427, 391, 403 s) including the 7-suite corrupted-reference control of each chunk, which fails the same tests with the same messages and local baselines on both engines. Per-test outcomes agree and no `tests/baselines/local` file is written by either engine in the real slice, so no engine or host change was needed.
