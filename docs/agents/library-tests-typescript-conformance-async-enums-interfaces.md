# Library Tests: TypeScript `conformance` runner, async / asyncGenerators / generators / enums / constEnums / interfaces / Symbols / root files (#1284)

Part of [library-tests-typescript.md](library-tests-typescript.md); the oracle, baseline IO, control and ratchet are those of [library-tests-typescript-compiler.md](library-tests-typescript-compiler.md), the conformance wiring that of [library-tests-typescript-conformance-expressions.md](library-tests-typescript-conformance-expressions.md).

**What it is**: `TS_SRC_DIR=<built TypeScript v6.0.3 checkout> uv run python scripts/run-ts-conformance-1284-oracle.py [--chunks as1,as2,if,mix] [--check-partition] [-- oracle options]` runs the `conformance` runner (`tests/cases/conformance`) for the directories `async` (1512 tests), `asyncGenerators` (30), `generators` (102), `enums` (84), `constEnums` (54), `interfaces` (396) and `Symbols` (96) plus the two files at the root of the directory, `fixSignatureCaching.ts` and `inferFromBindingPattern.ts` (12): 381 suites of 6 tests = 2286 tests, on Node and `jsse --node`, and compares them test by test plus every file under `tests/baselines/local`. The script loads `scripts/run-ts-conformance-expressions-oracle.py` (which points `scripts/run-ts-compiler-oracle.py` at the conformance runner) and adds only the rows of `scripts/ts_conformance_slices_1284.py` (`--slices-module`), its own ratchet file and the control below. Guards: `scripts/test_ts_conformance_slices_1284.py`, `tests/node_ts_conformance_1284.rs`.

**Chunks** (run one after the other, one oracle run each, so a crashed chunk loses nothing): `as1` (`async/es5`: 128 suites, 768 tests), `as2` (`async/es2017`, `async/es6`: 122, 732), `if` (`interfaces`: 66, 396) and `mix` (`asyncGenerators`, `generators`, `enums`, `constEnums`, `Symbols`, the root files and `async/asyncFunctionDeclarationParameterEvaluation.ts`: 65, 390). The root files are selected with `files:` (base names), so `--check-partition` also fails if another suite carries one of those names.

**Partition of the whole `conformance` runner.** `OWNERS` in `scripts/ts_conformance_slices_1284.py` assigns every top-level entry of `tests/cases/conformance` (52 directories and the two root files) to the issue that runs it: #1274 `types`, #1275 `expressions`, #1276 `classes`, `decorators`, `esDecorators`, `override`, #1277 `es6`, #1278 `es5`, `es7`, `es2016`-`es2025`, `esnext`, #1279 `statements`, `controlFlow`, `functions`, #1280 `parser`, `scanner`, `directives`, `pedantic`, `references`, #1281 `declarationEmit`, `emitter`, `ambient`, `additionalChecks`, #1282 `jsx`, `jsdoc`, `salsa`, `typings`, #1283 `moduleResolution`, `node`, `externalModules`, `internalModules`, `importAssertion`, `importAttributes`, `importDefer`, `dynamicImport`, `nonjsExtensions`, and #1284 the rest. `--check-partition` (Node only) fails unless (1) the chunks select disjoint suites that add up to the row `issue1284`, (2) six tests per suite equal the `oracle.json` pins of the group (the 7 directories plus the 12 tests of `runners.conformance.passed` that no bucket holds: 2286), (3) the root files are at the root, (4) every top-level entry on disk and every bucket of `oracle.json` has exactly one owner, and the root files account for the unbucketed 12 tests. A new upstream directory, or one that two issues claim, fails it.

**Control.** The shared corrupted-reference control (`scripts/ts_compiler_control.py`) picks baselines by file stem, so for a test with several `@target` configurations it corrupts e.g. `x(target=es2015).js` and then runs the suite `x.ts (@target: es5)`, which never reads it: on `async/es5` the control corrupted six references and made no test fail, and the oracle reported "the control checks nothing". The async tests are all of that kind (157 of the group's 381 suites are `@target` configurations). `scripts/ts_conformance_control_1284.py` keeps the modes, the file choice and the seven-suite limit but only considers the baselines of the configuration of the suite it picks (`stem(target=es5).ext` for `@target: es5`, `stem.ext` for an unconfigured one; an added reference keeps the configuration in its name). The wrapper swaps it in; the shared module is untouched.

**Compared**: the outcome of every test, the error message of a test failing on both, every file under `tests/baselines/local` byte for byte, and the seven-suite corrupted-reference control (it must fail identically on both engines). A test passing on Node and failing on jsse must be listed in `ts-suite/conformance-1284-known-failures.txt` (`full test title<TAB>issue`, filed under the tracker #1418; `--record` rewrites it); a listed test that passes fails the run. The file has no entries.
