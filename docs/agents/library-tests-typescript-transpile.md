# Library Tests: TypeScript `transpile` runner oracle

Split from [library-tests-typescript.md](library-tests-typescript.md) to keep each file under the 20,000-byte budget.

**What it is** (#1287): `TS_SRC_DIR=<built TypeScript v6.0.3 checkout> uv run python scripts/run-ts-transpile-oracle.py [--jobs N (at most 4)] [--batch-size N] [--test-timeout MS] [--no-control] [--corpus N|all] [--record] [--verbose] [--list] [slice ...]` runs TypeScript's `transpile` runner (`--runner=transpile`, `src/testRunner/transpileRunner.ts`) through mocha and `built/local/run.js` on Node and `jsse --node` and compares them test by test. The runner feeds each of the 22 files of `tests/cases/transpile` to `ts.transpileModule` (the single-file, no-program, `isolatedModules` path) and, with `@declaration`, to `ts.transpileDeclaration`, once per `declarationMap`/`sourceMap`/`inlineSourceMap` configuration (37 tests, the `transpile` count of `ts-suite/oracle.json`), and compares inputs, output, source map and reported diagnostics with `tests/baselines/reference/transpile`. Skips without `TS_SRC_DIR` (`--require` makes that an error). Design: `docs/adr/2026-10-29-0200-node-host-transpile-runner.md`; guards: `tests/node_ts_transpile.rs`, `scripts/test_run_ts_transpile_oracle.py`.

**Machinery.** It is the compiler oracle's ([library-tests-typescript-compiler.md](library-tests-typescript-compiler.md)), as the fourslash oracle's is: `scripts/run-ts-transpile-oracle.py` imports `prepare` and `mocha_run` from `run-ts-compiler-oracle.py` and the comparison, ratchet and known-failure IO of `ts_compiler_report.py`; what differs is `scripts/ts_transpile_slices.py` (the files and titles of the runner, the slice table, the mocha `--grep` of a batch), `scripts/ts_transpile_control.py` and the corpus mode. Each run has a private working directory of symlinks into the checkout (never written to) with its own empty `tests/baselines/local`.

**Compared** between the engines: the outcome of every test; the error message of a test failing on both; every file under `tests/baselines/local` byte for byte. A test passing on Node and failing on jsse must be listed in `ts-suite/transpile-known-failures.txt` (`full test title<TAB>issue`; `--record` rewrites the entries of the slice; empty today); a listed test that passes fails the run (ratchet); a Node failure, a test not run, or a Node passing count differing from `ts-suite/oracle.json` (37 for a whole-runner run) fails the run.

**Slices** (positional arguments, a '+' union; default `all`): `first:N`, `prefix:A-C`, `shard:I/N`, `files:a.ts`, `match:REGEX`, or a row of `SLICES` (`all`, `first10`, `declaration`, `sourcemap`; more with `--slices-module NAME`).

**Control.** Unless `--no-control`, five files re-run against corrupted input: the reference baseline of three appended to, rewritten or removed, and two input files with a declaration appended so the transpiled output no longer equals the reference. Node and jsse must fail the same tests with the same messages and write the same local files.

**Corpus mode** (`--corpus N|all`, `scripts/ts_transpile_corpus.py`, driver `scripts/ts-transpile-corpus.js`): the runner has only 22 inputs, so this goes wider. Over an even stride of N files (`all`: every file) of `tests/cases/{transpile,compiler,conformance}` with a `.ts`/`.tsx`/`.mts`/`.cts` extension (12,000 or so), `built/local/typescript.js` runs `transpileModule` under six option sets (`es2022-esnext`, `es5-commonjs-map` with `sourceMap`, `isolated-jsx` with `isolatedModules` and `jsx: preserve`, `react-umd-inline` with inline source map and sources, `node16-verbatim` with `verbatimModuleSyntax` and `react-jsx`, `decorators` with metadata and `importHelpers` for AMD) and `transpileDeclaration` once, reporting diagnostics. The sha256 of text, source map and diagnostics of every case is compared between the engines (chunks of 250 files per process, 4 processes at most); a throw is compared like an output.

**Cost.** The whole runner takes 3 to 5 s of jsse process time (the 13 MB bundle loads in about 2 s, each test is milliseconds, no `Program` or lib parse is needed); the control adds 3 s. The corpus takes about 8 s per 70 files on jsse (Node 1 s).
