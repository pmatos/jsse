# Library Tests: TypeScript `project` runner oracle

Split from [library-tests-typescript.md](library-tests-typescript.md) to keep each file under the 20,000-byte budget.

**What it is** (#1285): `TS_SRC_DIR=<built TypeScript v6.0.3 checkout> uv run python scripts/run-ts-project-oracle.py [--jobs N (at most 4)] [--batch-size N] [--test-timeout MS] [--no-control] [--record] [--verbose] [--list] [slice ...]` runs a slice of the `project` runner (`src/testRunner/projectsRunner.ts`) through mocha and `built/local/run.js` on Node and `jsse --node` and compares them test by test. Each `tests/cases/project/*.json` (316 cases) names a project root under `tests/cases/projects` and compiler options; for the `commonjs` and the `amd` module kind the runner builds a Program over a virtual file system (`lib.es5.d.ts`, `vfs` mounted on `tests/`), emits it and checks four baselines under `tests/baselines/reference/project/<case>/{node,amd}`: the module-resolution record (the case echoed with `resolvedInputFiles` and `emittedFiles`), the errors, every emitted JS/map file (only if the case sets `baselineCheck`) and the errors of recompiling the emitted `.d.ts`. So a case is 2 x 4 = 8 tests and the runner is the 2528 tests of `ts-suite/oracle.json`. Skips without `TS_SRC_DIR` (`--require` makes that an error). Guards: `tests/node_ts_project.rs`, `scripts/test_run_ts_project_oracle.py`.

**Machinery.** It is the compiler oracle's ([library-tests-typescript-compiler.md](library-tests-typescript-compiler.md)): `scripts/run-ts-project-oracle.py` imports `prepare` and `mocha_run` from `run-ts-compiler-oracle.py` and the comparison, ratchet and known-failure IO of `ts_compiler_report.py`; what differs is in `scripts/ts_project_slices.py` (the cases of the runner, the slice table, the mocha `--grep` of a batch) and `scripts/ts_project_control.py`. Each run has a private working directory of symlinks into the checkout (never written to) with its own empty `tests/baselines/local`.

**Compared** between the engines: the outcome of every test; the error message of a test failing on both; every file under `tests/baselines/local` byte for byte. A test passing on Node and failing on jsse must be listed in `ts-suite/project-1285-known-failures.txt` (`full test title<TAB>issue`; `--record` rewrites the entries of the slice); a listed test that passes fails the run (ratchet); a Node failure, a test not run, or (for the whole runner) a Node passing count differing from the 2528 of `ts-suite/oracle.json` fails the run.

**Control.** Unless `--no-control`, five cases re-run against corrupted input and both engines must fail the same tests with the same messages and write the same local files: a resolution record appended to, an `.errors.txt` rewritten, an emitted `.js` removed, a `.d.ts` appended to, and a case file with a `bug` key added (the record echoes the case). Node must fail at least the six tests the corruptions cause.

**Slices** (positional arguments, a '+' union): the terms of the compiler oracle (`first:N`, `prefix:A-C` on the file name, `shard:I/N`, `files:a.json`, `match:REGEX`) plus `startswith:out,sourcemap` and `except:out,sourcemap` (file name starts with / does not start with, case-insensitive), and the rows of `SLICES`: `core` (default, #1285: the 88 cases that are not the generated matrix, i.e. resolution, references, `declarations*`, `privacyCheck*`, `nodeModules*`, `jsFileCompilation*`, decorator metadata, `rootDirectory*`, `specifyExclude*`, `relative*`, `baseline*`, `circularReferencing*` ... 704 tests), `matrix` (#1286: `out*`, `sourcemap*`, `mapRoot*`/`maproot*`, `sourceRoot*`/`sourceroot*`, 228 cases, 1824 tests), `all`. Another range is a new row (or a module of your own with `--slices-module NAME`), not a change to the oracle.

**Cost.** Batches (`--batch-size`, default 30 cases = 240 tests) are one mocha process per engine, at most 4 processes at once over both engines. The projects are tiny, so the cost is the 13 MB runner bundle load and the 8 Programs per case: the 3 batches of `core` took 35 to 48 s each on jsse, 2 s on Node.

**Measured** (`core`, `CARGO_PROFILE_RELEASE_LTO=off`, 4 jobs): Node 704/704 passing in 6 s of process time, jsse 704/704 passing in 124 s of process time (about 50 s of wall time); control: 6 corrupted tests fail identically on both engines with identical local baselines. The known-failure list is empty: no engine or host bug showed up, and no engine change was needed.
