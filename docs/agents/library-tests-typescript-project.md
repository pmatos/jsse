# Library Tests: TypeScript `project` runner oracle

Split from [library-tests-typescript.md](library-tests-typescript.md) to keep each file under the 20,000-byte budget.

**What it is** (#1286): `TS_SRC_DIR=<built TypeScript v6.0.3 checkout> uv run python scripts/run-ts-project-oracle.py [--jobs N (at most 4)] [--batch-size N] [--test-timeout MS] [--no-control] [--record] [--verbose] [--list] [slice ...]` runs a slice of the `project` runner (`tests/cases/project/*.json`, 316 files = the 2528 tests of `ts-suite/oracle.json`) through mocha and `built/local/run.js` on Node and `jsse --node` and compares them test by test. Each json file names a small project under `tests/cases/projects` and the options to compile it with (`outFile`, `outDir`, `sourceMap`, `mapRoot`, `sourceRoot`, `declaration`, `resolveMapRoot`, `resolveSourceRoot`); the runner compiles it once as commonjs and once as amd on an in-memory file system and compares four things with `tests/baselines/reference/project/<name>/<node|amd>/`: the module resolution trace (`<name>.json`), the errors, every emitted file (`.js`, `.js.map`, `.d.ts`) and the errors of compiling the emitted declarations. A suite is one json file in one module kind (632 suites of four tests). Skips without `TS_SRC_DIR` (`--require` makes that an error). Guards: `tests/node_ts_project.rs`, `scripts/test_run_ts_project_oracle.py`.

**Machinery.** It is the compiler oracle's ([library-tests-typescript-compiler.md](library-tests-typescript-compiler.md)): `scripts/run-ts-project-oracle.py` imports `prepare` and `mocha_run` from `run-ts-compiler-oracle.py` and the comparison, ratchet and known-failure IO of `ts_compiler_report.py`; what differs is `scripts/ts_project_slices.py` (suites, slice table, mocha `--grep`) and `scripts/ts_project_control.py`. Each run has a private working directory of symlinks into the checkout (never written to) with its own empty `tests/baselines/local`, so a failing project test writes `tests/baselines/local/project/<name>/<module>/<file>` there and the runs of the two engines are compared file by file.

**Compared** between the engines: the outcome of every test; the error message of a test failing on both; every file under `tests/baselines/local` byte for byte. A test passing on Node and failing on jsse must be listed in `ts-suite/project-1286-known-failures.txt` (`full test title<TAB>issue`; `--record` rewrites the entries of the slice); a listed test that passes fails the run (ratchet); a Node failure, a test not run, or (for the whole runner, slice `all`) a Node passing count different from the 2528 of `ts-suite/oracle.json` fails the run.

**Control.** Unless `--no-control`, five suites of different json files re-run against a private copy of their reference tree in which one file is appended to (`<name>.json`, `.d.ts`), rewritten (`.js`) or removed (`.js.map`, `<name>.json`): Node and jsse must fail the same tests with the same messages (`New baseline created at ...`) and write the same local files.

**Slices** (positional arguments, a '+' union; terms as in the compiler oracle: `first:N`, `prefix:A-C` on the json file name, `shard:I/N`, `files:a.json`, `match:REGEX` on the suite title, or a row of `SLICES`): the default is `matrix`, the #1286 selection, the files named `out*`, `sourcemap*`, `mapRoot*`/`maprootUrl*` and `sourceRoot*`/`sourcerootUrl*` (absolute, relative and URL variants, with and without `outFile`/`outDir`): 228 files, 456 suites, 1824 tests; `out`, `sourcemap`, `maproot`, `sourceroot` are its four families, `all` is the whole runner. Another selection is a new row in `scripts/ts_project_slices.py` (or `--slices-module NAME`), not a change to the oracle.

**Cost.** Batches (`--batch-size`, default 60 suites) are one mocha process per engine, at most 4 processes at once over both engines. A project test is cheap once the process is up (the lib is `lib.es5.d.ts`): a batch of 12 suites took 14 s on jsse and 2 s on Node.

**Known failures.** `ts-suite/project-1286-known-failures.txt` (empty).

**Measured** (`CARGO_PROFILE_RELEASE_LTO=off` build, 4 jobs): the `matrix` slice (1824 tests, 8 batches) Node 1824/1824 in 18 s of process time, jsse 1824/1824 in 370 s; the whole runner (`all`, 2528 tests) Node 2528/2528, jsse 2528/2528 in 617 s; control: 5 corrupted suites fail identically on both engines with identical local baselines. No engine or host bug was found, so `ts-suite/project-1286-known-failures.txt` has no entries. Design: `docs/adr/2026-10-29-0200-node-host-project-runner.md`.
