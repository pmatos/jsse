# Node host mode: stdio streams, `tty` and `readline`

Status: accepted, epic #1214, issue #1232. `tty`, `readline`, `readline/promises`
and `internal/readline/*` are ported from Node v26.8.2 (`lib/tty.js`,
`lib/readline.js`, `lib/readline/promises.js`, `lib/internal/readline/*`,
`lib/internal/repl/history.js`, `lib/internal/fs/sync_write_stream.js`).
`internal/process/stdio.js` follows
`lib/internal/bootstrap/switches/is_main_thread.js`. Builds on the builtin
table of `2026-10-26-0854-node-host-mode.md`, `stream` (#1233), `events` and
`util` (#1224), and the event loop (#1312).

## Decision

1. **`process.stdin/stdout/stderr` are real streams, created on first access.**
   `defineStream` installs configurable, enumerable accessors on `process`, as
   in Node. `internal/process/stdio.js` picks the class by the kind of handle
   behind the descriptor, using the floor's `guessHandleType` (libuv's
   `uv_guess_handle`: a TTY, a regular file or any other character device
   such as `/dev/null`, a FIFO or unix socket, ...):
   TTY gives `tty.WriteStream`/`tty.ReadStream`; a file gives the vendored
   `SyncWriteStream` (stdout/stderr) or a `Readable` named `ReadStream`
   (stdin); a pipe or socket gives `Socket`. `isTTY`, `columns` and `rows`
   exist only on TTYs, so a piped run differs from a terminal run exactly where
   Node's does. Output is synchronous for all three kinds, as it is in Node on
   POSIX.
2. **No `net`.** `internal/stdio/socket.js` is the part of `net.Socket` the
   standard streams use: a `Duplex` with `decodeStrings: false`, a handle with
   `readStart/readStop/ref/unref`, `_write` calling the floor, an
   `'close'` event after destroy. `tty.ReadStream`/`WriteStream` are the
   upstream constructors on top of it (`ObjectSetPrototypeOf` onto this
   `Socket`). `new tty.WriteStream(fd)` does not fail for a non-TTY descriptor
   (Node's libuv does not either for pipes) and gets no window size.
3. **Floor: `__host_tty`** (`node_host_tty.rs`, unix only, private to
   `internal/host/tty`): `guessHandleType`, `isTTY`, `getWindowSize`
   (`TIOCGWINSZ`), `setRawMode` (`tcsetattr`; the original termios is saved per
   descriptor on the first raw call and restored by an `atexit` hook, so a
   normal exit or `process.exit` leaves the terminal cooked; a fatal signal
   while raw does not, Node's signal path does), a failure being the uv error
   (`setRawMode ENOTTY`), `write(fd, stringOrBytes)` (complete, waits out `EAGAIN`, throws the
   uv-shaped error, `EPIPE` included) and the fd 0 reader.
   Without the unix floor `internal/host/tty` is a small JS stand-in in
   `scripts/node-builtin-loader.js` (writes through `__host_write`, empty
   stdin, no TTYs). `ref`/`unref` on a stream act on fd 0 only, and
   `tty.ReadStream` of another descriptor throws `ERR_METHOD_NOT_IMPLEMENTED`
   (the reader is a single fd 0 reader).
4. **Reading fd 0 keeps the loop alive.** `stdinStart(cb)` asks a reader
   thread (spawned on first use) for one chunk; the thread posts the bytes
   into `agent_async_completions` and notifies the condvar the Node loop's poll
   phase sleeps on. The closure carries bytes only: it appends to
   `NodeLoopState.stdin.pending`; the loop's poll phase then calls the JS
   callback with `node_call` followed by `node_checkpoint`, never from inside a
   microtask drain, and requests the next read. The callback is rooted through
   `NodeLoopState::for_each_root`. A started, ref'd, not-ended reader counts in
   `node_loop_alive`; `stdinStop` (what `pause()` leads to) and `unref()`
   remove it, so `rl.close()` lets the process exit. Bytes that arrive while
   stopped are held and delivered on the next start. EOF ends the reader for
   good. Thread-blocked `read(2)` never delays exit: the CLI does not join it.
5. **Console writes through `process.stdout`/`stderr` like Node.**
   `internal/console/node.js` calls `internal/process/stdio`'s `write(fd, s)`:
   once `process.stdout` exists the text goes through its `write()` with
   Node's error handling (a failing write never throws out of `console.log`);
   until then nothing could have observed or replaced `write()`, so the text is
   written straight to the descriptor and a hello-world run does not load
   `stream`. Colors follow `colorMode: 'auto'`: objects are inspected with
   colors when the stream is a TTY with `getColorDepth() > 2` (or `FORCE_COLOR`
   asks), so a pty run colors `console.log({a: 1})` and also numbers and
   booleans, which is why the all-primitive fast path is only taken for strings
   when colors are on.
6. **readline.** `internal/readline/interface.js` is 48 KB upstream (budget
   20,000 bytes): `interface_state` holds the symbols and constants, `interface`
   the constructor and the core of the class, and `interface_io`,
   `interface_edit`, `interface_nav`, `interface_keys` hold method groups
   (written mechanically: the class has no `super`, so each group is an object
   literal whose methods are defined, non-enumerable, on `Interface.prototype`).
   Substituted: `string_decoder` (not on main until #1231) by
   `internal/readline/decoder` over `TextDecoder` with `stream: true`;
   `internal/process/permission` in `internal/repl/history` by an inline "no
   permission model". The history file path needs `fs.promises`, which lands
   with the fs tail; in-memory history is complete.
7. **Support in shared files.** `internal/errors.js` gains `ERR_INVALID_FD`,
   `ERR_INVALID_CURSOR_POS`, `ERR_USE_AFTER_CLOSE`; the loader takes
   `__host_tty` and loads `internal/process/stdio` after the console; the
   uncaught-exception printer falls back to a raw write when `process.stderr`
   cannot be created.

## Not covered

- `SIGWINCH`: windows are measured when the stream is created and by
  `_refreshSize()`; `'resize'` is not emitted on its own (no signal events).
- `process.stdin.setEncoding()` and `readable.setEncoding()` need the
  `string_decoder` module (#1231) and throw `ERR_UNKNOWN_BUILTIN_MODULE` until
  it is merged. `rl.question`, `'line'`, `for await`, `'data'`/`'end'`,
  `'readable'`, `pipe()` and raw-mode key input do not.
- A file on fd 0 is a `Readable` that is not an `fs.ReadStream` (no `path`,
  `bytesRead`, ...). `net.Socket` members beyond the stream API (`address()`,
  `setNoDelay`, `remoteAddress`) do not exist on pipe stdio.
- Windows: the floor is unix only, like the fs floor.

## Verification

- `./scripts/run-node-tty-oracle.sh` runs `scripts/tty-fixtures/*.fixture.js`
  on jsse `--node` and on Node in the modes each header lists: `pipe`, `file`
  and `pty` (all of stdin/stdout/stderr on one pseudo-terminal of a fixed size,
  driven by `pty-run.py`, with typed input). The observation is the exit status
  and the bytes written, escape sequences included; both engines run under
  `env -i` with a fixed `TERM`, so no CI color variable leaks in. 46 runs cover
  the shape of each stream per mode, `tty.isatty/ReadStream/WriteStream`,
  window size, `getColorDepth`/`hasColors` under `FORCE_COLOR`, `NO_COLOR` and
  `COLORTERM`, console output ordering with `process.stdout.write`, colors,
  `'line'`/`for await`/`question`/`readline/promises`, line editing and
  keypress in raw mode, cursor helpers, `pause()` and exit with stdin open,
  `process.exit()` with 2 MiB written, empty input. Each output must equal
  Node's recorded in `scripts/tty-fixtures/expected/` (`--update` rewrites it
  from Node; outputs over 4 KiB are recorded as length and digest).
- `tests/node_tty.rs` runs the oracle without Node and adds GC stress,
  tree-walker, `unref`, `EPIPE` and privacy checks.
