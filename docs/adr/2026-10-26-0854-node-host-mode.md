# Node host mode: native floor, JS prelude, default globals untouched

Status: accepted (#1215), epic #1214.

## Context

Running Node-style programs and the library harnesses (`scripts/run-library-tests.sh`)
needs `process`, `Buffer`, timers and, later, `fs`/`events`/`child_process`.
None of that is ECMAScript: the spec (§19, The Global Object) only permits
host-defined extra properties. The default global environment is what test262
measures, so any Node surface must be strictly opt-in and invisible otherwise.

## Decision

1. **Opt-in by `--node` only.** `Interpreter::enable_node_host` is called from
   `new_interp` when `--node` is given. `--prelude` (used by the test262
   runner) never enables it. With the flag off no new global exists; guarded
   by `host_globals_absent_when_floor_off` and the test262 baseline.
2. **Two layers.** A small native Rust *floor* of `__host_*` primitives
   (`src/interpreter/builtins/node_host.rs`) does only what JavaScript cannot:
   syscalls, entropy, clock, exit, and snapshots of argv/env/cwd. Floor
   globals are non-enumerable, configurable, and meant to be captured by the
   prelude and then `delete`d, as `__host_proxy_target` already is. The Node
   APIs themselves (`process`, `Buffer`, `util`, ...) are a JavaScript
   *prelude* built on the floor, so they iterate without recompiling Rust.
3. **Embedding and versioning (delivered by #1216).** Prelude modules live in
   one repository directory (`scripts/`: `node-shim.js` for
   `process`/`console`/`util`, `node-process-shim.js`, `node-buffer-shim.js`,
   `node-crypto-shim.js`; they stay there because the staged-file token
   ratchet bars moving an oversized file to a new path), are `include_str!`d into the
   binary and evaluated as global scripts in that fixed order by
   `Interpreter::load_node_prelude`. They are versioned with the jsse binary;
   there is no on-disk lookup, so no version skew. `enable_node_host` installs
   the floor only (so unit tests can exercise the bare primitives); the CLI's
   `--node` path then sets the launch arguments and calls `load_node_prelude`,
   so the prelude sees the real `argv`. Nothing outside `--node` parses or runs
   the prelude. It runs before the step budget is installed, so its steps are
   not charged to `--step-budget`. `process`, `Buffer`, `TextEncoder`, `TextDecoder` and
   `util` are made non-enumerable once the modules have run, as in Node, so
   `Object.keys(globalThis)` matches it (`crypto` stays enumerable, as in Node). The library harnesses no longer prepend
   shim files; only a library's own `LIB_SHIM`/`LIB_SHIMS` are prepended.
4. **Script arguments are verbatim, as in Node.** `jsse [jsse-options] script
   [args...]`: everything after the script path goes to `process.argv`
   untouched, including a literal `--` and flags such as `--version`. A single
   `--` before the script terminates jsse's own options (`node -- a.js -- z`
   consumes only the first). With `-e CODE` and no script, the first leftover
   non-option token and everything after it are script arguments. Splitting is
   uniform across modes; `process` is only observable under `--node`.
5. **`process` semantics.**
   - `argv` is `[execPath, absoluteScriptPath, ...args]` (no script entry for
     `-e`); `argv0` is the original `argv[0]`; `execPath` is the running binary.
   - `cwd()`/`chdir()` call the OS; `chdir` failures carry `code`, `errno`,
     `syscall`, `path`, `dest` and Node's message.
   - `exitCode` is validated like Node (integer or integer string; `undefined`
     and `null` clear it; otherwise `ERR_INVALID_ARG_TYPE`/`ERR_OUT_OF_RANGE`).
   - Exit-status precedence: `pending_exit` (`process.exit`, step budget 124)
     over an uncaught throw (1) over `process.exitCode` over 0. The status is
     the low byte of the code. `process.exit()` without an argument uses
     `exitCode`; `process.exit(0)` overrides it.
6. **`process.env` is a JS-owned object** seeded once from the OS environment
   by `__host_env_snapshot()`. Writes stringify like Node; the OS environment
   is never mutated (`set_var` is `unsafe` in Rust 2024 and agent threads
   exist). *Design note for child processes:* mutation of `process.env` must
   be visible to children spawned later; `child_process` (#1236) therefore
   takes `process.env` explicitly as the child's environment instead of
   inheriting the OS one. *Deliberate divergence:* real Node calls `setenv`;
   here any native reader of the OS environment (`TZ` for the time zone #263,
   `HOME` for `os.homedir` #1222) sees the startup snapshot, not JS edits, and
   a future reader must go through the prelude's `process.env`.
7. **Synchronous `fs` (#1217).** Unix-only floor primitives `__host_fs_*`
   (`node_host_fs.rs`, `node_host_fs_meta.rs`, shared plumbing in
   `node_host_fs_args.rs`, Node's uvException error shape in
   `node_host_fs_error.rs`) use the `libc` crate (already in the lock file via
   `clap`/`jemalloc`; now a direct `cfg(unix)` dependency) for descriptor
   syscalls. Descriptors are real OS descriptors. Paths arrive as strings or
   byte views and are used as raw OS paths. `readFile` hands the `Vec<u8>` it
   read straight to the result `ArrayBuffer` (sized from `fstat`) and
   `writeFile` writes from the view in place, so a large file is never copied
   on the Rust side. The JS half is three prelude scripts
   (`node-fs-support.js`: errors and validators, `node-fs-meta.js`: stat,
   directories, links, `node-fs-shim.js`: files, descriptors, assembly) that
   take the floor private like the other modules. The module registers itself on
   the provisional, non-enumerable `globalThis.__node_builtins.fs`, which the
   builtin loader takes private (ADR-2026-10-26-1400): reach it with `require("fs")`.
   Argument validation (`ERR_INVALID_ARG_TYPE`
   / `ERR_INVALID_ARG_VALUE` / `ERR_OUT_OF_RANGE`) mirrors Node and is the JS
   layer's job; syscall failures carry `code`, `errno`, `syscall`, `path` and
   `dest`. `scripts/node-fs-module.js` is unrelated: the library harnesses'
   virtual `fs`. The sync long tail (#1218) is in
   `docs/adr/2026-10-26-1719-node-host-fs-tail.md`; async forms are #1234.
   Oracle: `scripts/run-node-fs-oracle.sh`.

7. **Event loop (#1229).** `--node` swaps the default loop's behaviour for
   Node's, only once the prelude calls `__host_loop_install`; until then
   `event_loop.rs` is untouched and test262 sees the old loop
   (`tests/node_event_loop.rs` pins it). Split of work:
   - *JS* (`node-event-loop-shim.js`, `node-timers-shim.js`): the `nextTick`
     queue, `queueMicrotask`, `Timeout`/`Immediate` objects (`ref`, `unref`,
     `hasRef`, `refresh`, `Symbol.toPrimitive`), the `timers` and
     `timers/promises` modules, and the `process` events `exit`, `beforeExit`,
     `uncaughtException`, `unhandledRejection` and `warning`. `process` gets
     a small listener registry as its prototype, standing in for
     `EventEmitter.prototype` until the `events` module (#1223) replaces it.
   - *Rust* (`interpreter/node_event_loop.rs`, floor in `node_host_loop.rs`):
     the phase order (timers, poll, check), `node_checkpoint` (the whole tick
     queue, then promise jobs, repeated, then still-unhandled rejections),
     liveness (a ref'd timer or immediate, or awaited host-async work), the
     `reject_promise` hook that records promises rejected without a handler
     (re-checked via `is_handled` at processing time), and `node_host_finish`
     (`beforeExit` may start more work and re-enter the loop; then `exit`).
   - Timeouts are one-shot native timers re-armed by JS after an interval
     callback returns. Delays follow Node (`NaN`, `< 1` and `> 2**31-1` become
     1, with `TimeoutOverflowWarning` above the range), so `setTimeout(f, 0)`
     and `setTimeout(f, 1)` keep arming order. Unref'd timers still fire while
     the loop is alive for another reason.
   - Uncaught errors (main script, timer, immediate, tick, microtask) go to
     `uncaughtException` listeners; with none, the error is printed, `exit` is
     emitted with 1 and the process exits 1 (7 if a handler throws).
     Unhandled rejections are fatal (Node's `throw` mode) unless an
     `unhandledRejection` listener exists. A throwing `nextTick` callback
     abandons the current checkpoint, as in Node.
   - The `timers` modules are published on
     `globalThis[Symbol.for("jsse.node.builtins")]` until the CommonJS loader
     (#1219) can serve `require('timers')`.
   - *Deliberate divergences:* `setTimeout(f, 0)` against `setImmediate(g)`
     from the main script is nondeterministic in Node and here (jsse reaches
     the first loop turn sooner than Node, so the immediate usually wins);
     the fatal report is the error's stack plus a `Node.js` line, without
     Node's source excerpt; no `rejectionHandled` event; timers use the
     monotonic clock at full precision rather than libuv's millisecond tick.
     Other handle types (child processes, async fs) join the loop through the
     host-async completion queue, which keeps it alive while awaited.
   Oracle: `scripts/run-node-event-loop-oracle.sh` diffs
   `scripts/event-loop-fixtures/*.fixture.js` against Node.
   `HOME` for `os.homedir` before #1222) sees the startup snapshot, not JS
   edits, and a future reader must go through the prelude's `process.env`, as
   `os.homedir`/`os.tmpdir` do.

## Rejected

- **A native Rust `process` object**: every Node surface would become Rust,
  slowing iteration and bloating the floor.
- **Mutating the OS environment with `set_var`**: unsafe in Rust 2024 and
  thread-hostile (Atomics agents).
- **clap `trailing_var_arg`**: it strips the first `--`, so `node a.js -- x`
  would differ from Node.

## Consequences

- The floor stays small and auditable; each new primitive is a deliberate,
  documented addition.
- `jsse app.js --version` now passes `--version` to the script instead of
  printing jsse's version; jsse options must precede the script.
- `process.env.TZ = ...` does not retarget the native time zone.
- Parse errors keep exit status 2 (Node uses 1).

## Addendum: embedded builtin modules (#1221)

Status: accepted, epic #1214. First consumer: `path`; the CommonJS loader
(#1219) resolves `require` against this table.

1. **A name-to-source table in Rust.** `src/interpreter/builtins/node_host_builtins.rs`
   maps a module id (`"path"`, `"path/posix"`, `"internal/errors"`, ...) to a
   source file `node-lib/<id>.js`, `include_str!`d so the sources are versioned
   with the binary (no on-disk lookup, no skew). One `builtin!("<id>")` line adds
   a module. The table is exposed to the prelude only as the floor primitive
   `__host_builtin_source(id)` (string or `undefined`); the floor is installed by
   `enable_node_host`, so nothing exists without `--node`.
2. **Evaluated lazily, by the prelude.** `scripts/node-builtin-loader.js` is the
   last prelude script before `hide-globals`. It captures `__host_builtin_source`
   and deletes the global. Nothing is parsed at startup: a module is compiled
   with indirect `eval` the first time it is required, and the `primordials`
   object is built on the first load, so a launch that never touches a builtin
   pays only for the loader itself.
3. **Module shape is Node's own.** A source is the body of
   `function (exports, require, module, process, primordials)`, as in Node's
   bootstrap, so files derived from `lib/` need no edits beyond what jsse
   requires. `primordials` follows Node's naming (`ArrayPrototypeJoin`,
   `StringPrototypeSlice`, `ObjectKeys`, ...); add helpers there when a port needs
   one. `require` inside a module resolves other table entries only;
   `internal/util/inspect` is bound to the prelude's `util.inspect`.
4. **`internal/` is private.** The public entry point refuses any id starting
   `internal/` (or `node:internal/`) with `ERR_UNKNOWN_BUILTIN_MODULE`, as Node
   does for user code. `node:` prefixes are accepted.
5. **Reaching a builtin.** `require("path")` / `require("node:path")` (#1219,
   ADR-2026-10-26-1400). The hidden `__node_builtin(id)` that #1221
   introduced as a testing hook is gone. A builtin that needs more host
   primitives adds a `__host_*` function to the floor; modules never reach the
   interpreter any other way.
6. **Why `node-lib/` and not `scripts/`.** The prelude shims are single-file
   scripts that predate this table; the builtin modules are a tree of small
   files named after the ids they implement (`node-lib/internal/path/posix.js`
   is `internal/path/posix`), so the directory is the table's namespace. Files
   stay under the 20,000-byte staged-file budget, which is why `win32` is two
   files (`internal/path/win32_a`, `win32_b`, merged with `ObjectAssign`) and
   the vendored minimatch is split at its bundle boundaries.
7. **`path`.** Derived from Node v26.8.2 `lib/path.js` (MIT; license text kept in
   `node-lib/internal/path/common.js`). `matchesGlob` is real: it embeds the
   minimatch Node ships (ISC; `node-lib/internal/deps/minimatch/`) behind the
   `matchGlobPattern`/`createMatcher` half of `lib/internal/fs/glob.js`
   (`node-lib/internal/path/glob.js`); the directory-walking `Glob` class is not
   embedded. `internal/errors` is a subset of Node's (`E()` codes are added as
   modules need them). Edits to the vendored minimatch (re-apply after a
   re-sync): comment and method-name typo fixes; `Minimatch` is split into a
   base class (`optimize.js`) and the rest to stay under the file budget; and
   the `set;` field is written `'set';` because jsse's parser rejects a bare
   `set;`/`get;` class field (#1313; revert the edit when that is fixed).
   Primordials are snapshotted when the prelude runs, before user code, and
   uncurried on first use of each name. Verification:
   `scripts/run-node-path-oracle.sh` (Node's own `test-path-*.js` plus a
   deterministic 41k-call corpus diffed against Node) and `tests/node_path.rs`.

## Addendum: events, EventTarget, AbortSignal (#1223)

Status: accepted, epic #1214. Ported from Node v26.8.2 (`lib/events.js`,
`lib/internal/event_target.js`, `lib/internal/abort_controller.js`,
`lib/internal/per_context/domexception.js`; MIT) into the builtin table.

1. **Layout.** `events` (the `EventEmitter` class) with the statics `once`, `on`,
   `getEventListeners`, `getMaxListeners`, `listenerCount` split into
   `internal/events/statics` (which reaches `events` lazily), plus
   `internal/events/abort_listener`. `Event`/`CustomEvent` are
   `internal/event_target_event`; `EventTarget` and `defineEventHandler` are
   `internal/event_target`; `AbortController`/`AbortSignal` are
   `internal/abort_controller`. Support modules: `internal/webidl` (DOMString,
   interface and sequence converters only), `internal/fixed_queue`,
   `internal/perf/utils` (`now`, process-relative until perf_hooks #1227),
   `internal/per_context/domexception`, `internal/process/warning`.
   `internal/errors`, `internal/validators` and `internal/util` grew the codes
   and helpers these need.
2. **Web globals.** `Event`, `EventTarget`, `CustomEvent`, `AbortController`,
   `AbortSignal` and `DOMException` are installed by `node-builtin-loader.js`
   from its `LAZY_GLOBALS` table with Node's `exposeLazyInterfaces` shape: a
   non-enumerable accessor that loads the module on first touch and then
   settles into a writable, non-enumerable data property. Nothing is parsed
   until a script touches one; they do not exist without `--node`. A new
   global is one line in that table.
3. **`process` can be rebased onto the real emitter.** Nothing here edits
   `process`. `internal/process/warning` calls `process.emitWarning` when the
   prelude has it (#1229) and otherwise emits `'warning'` on the next tick after
   the default stderr line, so the module works before and after the event-loop
   work; delete the fallback when `process.emitWarning` is guaranteed. Once
   `process` inherits from `events` (`Object.setPrototypeOf(process,
   EventEmitter.prototype)` plus `EventEmitter.call(process)` from the loader),
   `process.on/emit` get the full Node semantics and fixtures that need them can
   be ungated (item 7).
4. **Timers.** `AbortSignal.timeout` uses the global `setTimeout`/`clearTimeout`
   captured when `internal/abort_controller` first loads, and calls
   `timeout.unref()` only if the timer object has it: until #1229 timers return
   numbers, so a pending `AbortSignal.timeout` keeps the process alive there.
5. **Primordials.** Promise statics (`PromiseResolve`, `PromiseReject`,
   `PromiseWithResolvers`, ...) are bound to `Promise`, as Node does
   (`copyPropsRenamedBound`); they threw "Promise.resolve requires an object"
   before.
6. **Not ported, and why.** `EventEmitterAsyncResource` (needs `async_hooks`);
   `NodeEventTarget` (used by worker and message ports); the enhanced stack of an
   unhandled `'error'` (`Error.captureStackTrace`, #1228); `AbortSignal`
   structured-clone transfer; `kEnhanceStackBeforeInspector`. Inspection output
   (`EventEmitter {...}`, `[Object]` in the max-listeners warning text, custom
   inspect of `AbortController`) follows the prelude's `util.inspect` until
   #1224. Two cross-module gaps: a throwing `EventTarget` listener is reported
   with `process.nextTick(() => { throw err; })`, which the current shim runs as
   a promise job and swallows until #1229; and the lazy `DOMException` is a new
   class, so the host-created `DataCloneError`/`InvalidCharacterError` errors of
   `structuredClone` and `atob` are not instances of it (they should inherit
   from it once both exist).
7. **Verification.** `scripts/run-node-events-oracle.sh`: 30 of Node's own tests
   (`scripts/events-fixtures/manifest.txt`) through a small
   `assert`/`common`/`node:test` harness, plus a corpus diffed against Node and
   pinned by digest. Four tests are gated by manifest markers and by probes in
   the oracle and `tests/node_events.rs`: `needs-process-events` (`process.on/emit`
   work: all four) and `needs-inspect` (`util.inspect(x, {depth: -1})` names the
   class, #1224: the three max-listeners-warning tests, which assert `[EventEmitter]`
   in the warning text). A probe that passes opens its gate by itself. Run on top
   of PR #1312, `test-event-emitter-special-event-names` passes and the other
   three fail only on the `[Object]` text, hence `needs-inspect`.
   Node's tests that are not included: those that
   `require('internal/...')` (`test-eventtarget.js`, `test-events-on-async-iterator.js`,
   ...) because user code cannot reach internals, `.mjs` files, `domain`/`stream`
   users (`test-event-emitter-prepend`, `-remove-listeners`,
   `-no-error-provided-to-error-event`), `test-event-emitter-errors` (needs
   `util.inspect.custom`, #1224), `test-events-uncaught-exception-stack` (child
   process) and `test-abortsignal-cloneable` (structured clone). Three
   `test-abortcontroller` subtests are skipped on jsse only (harness
   `__eventsJsseSkips`): one needs `util.inspect.custom` and two assert that
   `$262.gc()` collects a `WeakRef` target (#1317).

8. **V8 Error API (#1228).** `stack`, `captureStackTrace`, `stackTraceLimit`, `prepareStackTrace`, CallSite: see `2026-10-26-1000-node-host-v8-errors.md`.
