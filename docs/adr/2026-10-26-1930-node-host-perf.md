# Node host mode: process metrics and perf_hooks

Status: accepted (#1227), epic #1214. Extends `2026-10-26-0854-node-host-mode.md`.

`tsc --extendedDiagnostics` reads `process.memoryUsage()`, `performance.now()`,
`performance.timeOrigin`, `performance.mark/measure` and a `PerformanceObserver`
from `perf_hooks`; the build chain reads `process.platform`, `arch`,
`versions` and `umask`. This adds them, with Node as the oracle.

**Floor.** One hidden global, `__host_process` (`node_host_process_metrics.rs`),
holds the queries that cannot be JavaScript: `info()` (pid, ppid, platform,
arch, title, jsse version), `now()`, `timeOrigin()`, `memoryUsage()`, `rss()`,
`cpuUsage()`, `resourceUsage()` and `umask()`. `scripts/node-process-metrics.js`
(loaded after `node-process-shim.js`) captures it for `process`;
`node-builtin-loader.js` then deletes the global and seeds it as the private
module `internal/host/process`, with a `load` property that is its own
`requireBuiltin`. The `process` methods are thin wrappers that call
`internal/process/per_thread` through `load` on first use, so startup does not
parse the validators or errors and the argument checks are Node's
(`ERR_INVALID_ARG_TYPE`, `ERR_OUT_OF_RANGE`, `ERR_INVALID_ARG_VALUE`).
`hrtime()` and `hrtime.bigint()` stay the fast native-backed functions; only
the error path goes through `per_thread`.

**Process properties.** `platform`, `arch`, `pid`, `ppid` and `title` come from
`info()`, with the same descriptors Node gives them. `platform`/`arch` use the
`os` binding's mapping (`node_platform`/`node_arch`) and its test override, so
they are no longer the constants `linux`/`x64` (#1314) and `internal/util`'s
`isWindows`/`isMacOS` and the `path` flavour follow the host. `title` is the
launcher's `argv[0]`, as libuv reports it, and a plain data property (Node's
setter coerces to string; ours does not). `version`/`versions.node` are the
Node release whose `lib/` the embedded modules derive from (v26.8.2) plus a
`jsse` entry; no other component versions are claimed (`v8`, `openssl`, ...
are absent on purpose: `internal/util/types` and real code branch on them).
`release` mirrors Node's shape, `features` lists Node's keys with honest
values (`inspector`, `tls`, `uv`, `ipv6`, `typescript` and the rest are
`false`), and `config` is a small frozen `{ variables, target_defaults }`.
`execArgv` and `debugPort` get their Node defaults.

**Metrics and their limits.**
- `performance.now()` and `process.hrtime` share one clock, zero at the moment
  the floor starts (the process time origin); `performance.timeOrigin` is that
  moment in epoch milliseconds with microsecond resolution.
- `memoryUsage()` on Linux reads `/proc/self/status`: `rss` is `VmRSS`,
  `heapTotal` is `VmData` and `heapUsed` is `RssAnon`, the allocator's mapped
  and resident anonymous memory, so they rise and fall with allocation. Other
  unixes report `ru_maxrss` for all three. `external` and `arrayBuffers` are 0.
- `cpuUsage()`/`resourceUsage()` are `getrusage(RUSAGE_SELF)`; `threadCpuUsage`
  is the same call (one thread). Windows has no native queries and reports 0.
- `umask()` is `umask(2)` (read by setting and restoring); 0 on Windows.
- There is no libuv loop or GC event source: `nodeTiming.loopStart` is -1,
  `eventLoopUtilization()` and `idleTime` are 0, and `gc` observers never fire.

**perf_hooks.** `node-lib/perf_hooks.js` and `internal/perf/{performance,
performance_entry,observe,usertiming,nodetiming,resource_timing,timerify,
event_loop_utilization,event_loop_delay}.js` are Node v26.8.2 verbatim apart
from three substitutions: `internalBinding('performance')` is
`internal/perf/binding` (constants, milestones, `now`, no-op GC hooks), the
global `structuredClone` replaces `internal/worker/js_transferable`, and
`setResourceTimingBufferSize` converts with `>>> 0` instead of the WebIDL
converter. `internal/perf/utils` now measures from the process time origin, so
`Event#timeStamp` does too. `performance`, `PerformanceObserver`,
`PerformanceEntry`, `PerformanceMark`, `PerformanceMeasure`,
`PerformanceObserverEntryList` and `PerformanceResourceTiming` are lazy
globals like `AbortController`: the module loads on first touch.

`internal/histogram.js` is a JavaScript port of the HdrHistogram arithmetic
(sub-bucket math, equivalent-value ranges, the percentile iterator), not of
Node's file: `createHistogram()` returns the same `min`, `max`, `mean`,
`stddev`, `percentile(p)` and `percentiles` as Node for the same inputs,
including the 3-figure rounding of large values. Not ported: the Node 26
statistics extras (`cdf`, `ccdf`, `countAt`, `ewma*`, `burnRate`, `skewness`,
`kurtosis`, `ksTest`/`welchTest`/..., `linearBuckets`, `percentileCI`,
`percentilesAt`, `subtract`, `recordCorrected`) and structured-clone transfer.
`monitorEventLoopDelay()` records the gap between ticks of an unref'd
`setInterval`, as Node's uv timer does; `samplePerIteration` is validated and
ignored.

**Verification.** `scripts/run-node-perf-oracle.sh` diffs
`scripts/perf-fixtures/probe.js` against Node byte for byte (twice, plain and
`--no-bytecode`): identity, shapes, descriptors and function names, argument
errors, user timing and observer ordering, the histogram numbers, and booleans
for the moving values (monotonic, plausible). `tests/node_perf.rs` needs no
Node (including `JSSE_GC_STRESS`); the in-crate test in
`node_host_process_metrics.rs` overrides the platform to check `win32`,
`darwin` and `linux`.
