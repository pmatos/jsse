# `execute` fuzz target: in-process, bytecode VM vs tree-walker

Status: accepted (#1174); lifts the "in-process differential target" out-of-scope bullet of ADR 0004.

## Context

Only `parse` ran in-process (ADR 2026-10-23-0854). The interpreter, GC,
bytecode VM, inline caches, typed arrays and the other built-ins had no fuzz
coverage, and `differential` runs jsse as a subprocess against `node` at tens
of executions per second with no sanitizer. The step budget (ADR
2026-10-23-1200) makes running arbitrary scripts in-process safe. The engine
has two execution modes that must implement the same semantics, so one mode is
the oracle for the other and no `node` is needed.

## Decision

- `fuzz/fuzz_targets/execute.rs` calls `jsse::fuzz_execute_bytes`. The runner
  lives in the library (`src/lib.rs`) because `Interpreter` internals are
  `pub(crate)`. Each input runs in a fresh `Interpreter` on the bytecode VM,
  then again on the tree-walker, each dropped afterwards (the process is
  long-lived, unlike the CLI).
- A finding is a panic, abort or sanitizer report, or an **Execution
  Divergence** (reported as a panic starting `execution divergence`): a
  difference in observable outcome between the two modes. It is distinct from
  the `Divergence Tier` of `differential`, which compares jsse with node.
  (`CONTEXT.md` is at its size limit, so the term is defined here.)
- The compared signature is the outcome kind (completed, threw, parse error),
  the rendered completion value or thrown error `name`, and the captured host
  output. Error messages are not compared: their wording is not specified and
  the modes may phrase them differently. Step counts are not compared: they
  legitimately differ between modes.
- Budget exhaustion in either run skips the comparison (the modes stop at
  different points). It is never reported as a hang. The budget is 20,000 steps
  per run: 100,000 cost over a second per input under ASan with debug
  assertions, while 20,000 gives about 200 executions per second.
- Determinism hooks, all inert unless enabled: `print` / `console.*` output is
  captured into a buffer; timers use a virtual clock that jumps to the next
  deadline instead of sleeping, so ordering never depends on real time;
  `Math.random` is seeded identically for every realm, including `ShadowRealm`
  and `$262.createRealm` realms.
- Inputs containing the identifiers `agent`, `waitAsync` or `sleep` are not run
  at all: `$262.agent.start` spawns an unbudgeted thread, `agent.sleep` really
  sleeps and `Atomics.waitAsync` parks the event loop on a condvar. Inputs
  containing `Date`, `DateTimeFormat`, `Temporal`, `WeakRef`, `FinalizationRegistry`, `$262`,
  `Atomics`, `SharedArrayBuffer`, `performance` or `gc` still run in both modes
  (for panic and sanitizer coverage) but are not compared. Matching is on
  identifier boundaries.
- Seeds: `fuzz/corpus/execute/` holds copies of `tests/*.js` plus ~40 small
  test262 tests generated by `scripts/gen-fuzz-execute-corpus.py` with the
  harness (`sta.js`, `assert.js`) inlined; the generator rejects any seed that
  would trip the markers above, so a seed's comparison really runs. The
  `recursion-limit-*` and `string-max-length*` tests are excluded: they depend
  on the plain release build's stack limits or allocate gigabytes.
- ClusterFuzzLite: `.clusterfuzzlite/build.sh` builds `execute` next to
  `parse`, so it runs in the PR (code-change) and batch jobs under ASan with
  `max_len = 16384` (`execute.options`) so seeds that carry the harness are not
  truncated. ClusterFuzzLite splits `fuzz-seconds` between the targets.
- Unbudgeted work still ends in a libFuzzer timeout or OOM artifact (regex
  backtracking, `"x".repeat(2 ** 28)`, expression-bodied-arrow iterator loops,
  exponential arrow recursion; see the step budget ADR "Not covered"). Those
  are real findings about missing resource limits; triage them as such.

## Consequences

- A latent bug or mode difference can fail the `ClusterFuzzLite PR` check on an
  unrelated PR; there is no earlier `main` build of `execute` to filter it
  against. The seed corpus replays cleanly and a 4-minute local run at the CI
  flags (about 50,000 executions) found nothing before this landed.
- Rejected: comparing step counts or error messages (noise); comparing only
  against `node` (slow, no sanitizer, wrong oracle for an engine-internal
  invariant).
- Follow-ups: dictionaries or a grammar-aware mutator (the structure-aware
  generator landed as `execute_ast`, ADR 2026-10-23-1630), module inputs, counting
  function entries and native loops in the budget, a bytecode vs tree-walker
  check over test262.
