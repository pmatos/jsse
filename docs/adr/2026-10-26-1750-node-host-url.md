# Node host mode: url, querystring, punycode and the WHATWG globals

Status: accepted (#1230), epic #1214. Extends `2026-10-26-0854-node-host-mode.md`.

Reachable through `require("url")`, `require("querystring")` and
`require("punycode")` (CommonJS loader, #1219).

1. **Node's own JavaScript, a JavaScript binding.** `url`, `querystring`,
   `punycode` and the `URL`/`URLSearchParams` classes are Node v26.8.2's
   `lib/` sources (MIT), split across `node-lib/` to stay under the file
   budget: `url.js`, `internal/url.js` (file URLs, `domainTo*`,
   `urlToHttpOptions`), `internal/url/url.js` (`URL`), `internal/url/params.js`
   (`URLSearchParams`; the two classes share private state through the `hooks`
   object in `internal/url/util.js`), `internal/url/legacy_parse.js` and
   `legacy_resolve.js` (`url.parse`/`resolve`). Node's `internalBinding('url')`
   is ada (C++); `internal/url/binding.js` replaces it with the same interface
   (`parse`, `update`, `canParse`, `format`, `pathToFileURL`, `domainTo*` and a
   `urlComponents` array with ada's `url_aggregator` offsets), so the class
   code is unchanged. The binding sits on a WHATWG URL Standard parser written
   for this repo: `parser.js` (basic URL parser with state overrides, driving
   every setter), `host.js` (IPv4, IPv6, opaque and domain hosts),
   `encode.js` (percent-encode sets, UTF-8), `serialize.js`.
2. **IDNA is a floor primitive.** UTS #46 needs Unicode mapping, normalization,
   bidi and joiner tables, which cannot reasonably live in JavaScript. The floor
   gains `__host_idna_to_ascii(s)` (string, or `undefined` on failure) and
   `__host_idna_to_unicode(s)` (`src/interpreter/builtins/node_host_idna.rs`),
   backed by the `idna` crate (new dependency; `Cargo.lock` gains only `idna`
   and `idna_adapter`, which reuse the existing ICU4X crates, and every licence
   is already in `deny.toml`). The builtin loader takes both off the global
   object and hands them to the modules as `internal/url/idna`;
   `internal/url/domain.js` wraps them. They match ada, not the stricter
   spec/ICU behaviour: an all-ASCII name is only lowercased (`xn--` labels
   included), a name with non-ASCII is validated label by label. Known
   divergence, not covered by the corpus: for about 400 code points added in
   Unicode 14-17 and for some ContextJ sequences Node accepts what the `idna`
   crate rejects.
3. **Globals.** `URL` and `URLSearchParams` are installed by the builtin loader
   as non-enumerable accessors that turn into ordinary non-enumerable data
   properties on first read or write, so a launch that never touches them does
   not parse the url sources. Until then `Object.getOwnPropertyDescriptor`
   shows `get`/`set` instead of `value`. They do not exist without `--node`.
4. **Differences from Node.** No `DEP0169`/`DEP0040` runtime warnings (the
   prelude has no `process.emitWarning`). Not embedded: `URLPattern`,
   `URL.createObjectURL`/`revokeObjectURL` (no `Blob`), the Buffer-returning
   file-path variants. Objects carry `Symbol.for('nodejs.util.inspect.custom')`
   methods, but `console.log` only uses them once `util.inspect` honours the
   symbol (#1224). `internal/host/buffer` is a loader-provided stand-in exposing the global
   `Buffer` for `querystring` (not reachable as `buffer`) until #1231 adds the
   real module. The url sources are loaded lazily, so they use primordials for
   the helpers in `internal/url/util` and `encode`, but the parser and the
   legacy `url.parse` still call methods on `String.prototype`/`RegExp.prototype`
   through the live objects: patching those before the first `URL` use changes
   behaviour, unlike Node. The error
   factory `E()` now runs message functions with the error as `this` and sets
   `code` first, as Node does (`ERR_INVALID_URL` stores `input` and `base`).
5. **Verification.** `scripts/run-node-url-oracle.sh` runs a deterministic
   ~29k-line corpus (`scripts/url-fixtures/corpus-*.js`) on `jsse --node` and
   Node and diffs stdout/stderr, then checks the digest in
   `corpus.digest`: random and hand-written WPT-style parse vectors (urltestdata
   shapes, with and without bases), every setter (random and setters_tests
   shapes), `URLSearchParams`, legacy `url.parse/format/resolve` with flags,
   `fileURLToPath`/`pathToFileURL` round trips with `windows: true|false`,
   `domainTo*`, IDNA code point sweeps, `querystring`, `punycode`.
   The WPT data files are not available offline, so the vectors are written to
   their shapes and Node supplies the expected values. `tests/node_url.rs`
   pins the digest (bytecode and tree-walker), the opt-in gate, the lazy
   globals, error shapes and a GC-stress run.
