# Node host mode: the zlib module

Status: accepted (#1239), epic #1214. Extends `2026-10-26-0854-node-host-mode.md`
and builds on `stream` (#1233, `2026-10-26-2000-node-host-stream.md`) and
`crypto` (`2026-10-26-1930-node-host-crypto.md`, same native-binding pattern).

**`zlib`** (#1239). `require("zlib")` / `require("node:zlib")` is Node v26.8.2's
own `lib/zlib.js`, split across `node-lib/zlib.js` (facade: convenience
methods, `crc32`, `constants`, `codes`) and `node-lib/internal/zlib/`:
`base.js` (`ZlibBase`, `processChunk[Sync]`, `processCallback`, the buffer
helpers), `classes.js` (`Zlib`, `Deflate`...`Unzip`, the Brotli classes),
`constants.js` (`zlib.constants` as Node reports it), `errors.js`, `util.js`
and `binding.js`. `binding.js` plays the part of `internalBinding('zlib')` over
a private native binding, `__host_zlib` (`src/interpreter/builtins/
node_host_zlib.rs`, `node_host_zlib_ctx.rs`), which the builtin loader captures,
deletes from the global object and seeds as `internal/host/zlib`. Nothing here
exists without `--node`; the default global environment is unchanged.

## Decisions

1. **Vendored JS over a faithful port of the native handle.** Streams, the
   sync/callback/stream APIs, chunking, `flush()`, `params()`, `maxOutputLength`,
   option validation and the error shapes are Node's code paths. The native
   half is a line-for-line port of `ZlibContext` in `src/node_zlib.cc`
   (`Init`, the lazy `InitZlib`, `DoThreadPoolWork`, `GetErrorInfo`,
   `ErrorForMessage`, `ResetStream`, `SetDictionary`, `SetParams`): UNZIP
   decides gzip vs zlib from the first two bytes even when they arrive in
   separate writes, GUNZIP restarts on a following member unless
   `rejectGarbageAfterEnd` (trailing zero bytes are padding), `Z_NEED_DICT` is
   answered from the dictionary and retried (INFLATERAW sets it at init),
   `Z_BUF_ERROR` with `Z_FINISH` and room left is "unexpected end of file", and
   errors surface as `onerror(message, errno, code)` with zlib's own `msg`.
2. **Dependency: `libz-rs-sys` 0.6** (Zlib licence, already allowed by
   `deny.toml`; pure Rust, a port of zlib-ng with the zlib C API, features
   `std` and `rust-allocator`; it pulls in `zlib-rs` only). Chosen over
   the high-level deflate wrapper crates (the usual `Read`/`Write` adapters)
   because their safe API cannot express `Z_BLOCK`, `memLevel`, a strategy
   change in `deflateParams` or `inflate` error messages
   (`strm.msg`), all of which Node's binding and its tests observe; over
   `miniz_oxide` for the same reason and because its output is further from
   zlib's; over `libz-sys` because that compiles C zlib, and the issue asks for
   a pure-Rust codec. The `unsafe` is confined to `node_host_zlib_ctx.rs`
   (raw `z_stream` calls on a boxed, never-moved stream; buffer pointers are
   set for one call and cleared) and one `crc32` call.
3. **Writes.** `write()` stores the arguments on the handle and runs the work
   from a `setImmediate` job; Node uses a thread-pool job whose completion is
   likewise never synchronous. No worker thread: the work reads and writes
   buffers owned by the interpreter. `writeSync` runs inline. Input and output
   are borrowed in place (a copy only when both are windows of one
   `ArrayBuffer`), so a 32 MiB input fed through 16 KiB output chunks does not
   copy per chunk. `close()` during a pending write is deferred until the job
   ran, `reset()` during one throws, as in Node. Every JS value (write state,
   callback, in-flight buffers) lives on the JS handle; the Rust table holds
   only `z_stream` state, so GC needs no new roots.
4. **`params()`.** Node leaves `next_out` pointing at the last output buffer.
   Here the buffers are cleared after each call, so `deflateParams` runs with
   zero output space: it reports `Z_BUF_ERROR` (tolerated, as in Node) and
   changes the parameters once nothing is pending, which is the state `params()`
   creates by flushing with `Z_SYNC_FLUSH` first.
5. **`crc32`** is `libz_rs_sys::crc32` (strings as UTF-8, lone surrogates as
   U+FFFD, as in Node), chunked below 2^30 bytes per C call.

## Compressed bytes versus Node

Node's zlib is Chromium's fork (`process.versions.zlib` is `1.3.2.1-motley`):
a 4-byte hash and SIMD match finders make its deflate output differ from
vanilla zlib 1.3 (checked against CPython's zlib) at almost every level, and
`zlib-rs` follows zlib-ng, which differs again (levels 1-6 use zlib-ng's
`deflate_quick`/`deflate_medium`). No available backend is byte-identical to
Node at every level, so:

- **Identical to Node, pinned by the algorithm, tested by bytes:** level 0
  (stored blocks), `Z_HUFFMAN_ONLY` and `Z_RLE` at every level, empty input,
  headers and trailers (gzip header `1f8b08000000000000 03`, adler32, crc32,
  window-bits/level flag bytes), dictionary ids, sync-flush markers.
- **Same container, different match choices (round trip and cross-decode
  only):** the default and filtered/fixed strategies at levels 1-7 and 9, and
  often 2-3 more on other inputs. Sizes are within a few percent of Node's at
  level 6; level 1 is larger (zlib-ng's quick path trades ratio for speed).
  Level 8 matched on both inputs measured. Inflate is exact for every stream.
- Tiny inputs match except at level 1 (the oracle's "hello world hello world..." input).

A stream that is neither ended nor destroyed keeps its `z_stream` until exit:
the engine runs no `FinalizationRegistry` callbacks. Init is lazy, so a handle
whose constructor failed validation holds no zlib state yet.

## Not provided

- **Brotli.** The classes, `brotli*` functions, `createBrotli*` factories and
  every `BROTLI_*` constant are present and unchanged, but constructing a
  Brotli stream throws `ERR_FEATURE_UNAVAILABLE_ON_PLATFORM`. The only pure-Rust
  codec with an encoder is the `brotli` crate (`BSD-3-Clause AND MIT`, with
  `alloc-no-stdlib`/`alloc-stdlib` under `BSD-3-Clause`); `deny.toml` allows
  neither, and changing its allow-list needs a human ruling (see the PR). In a
  trial its output matched Node's brotli 1.2.0 byte for byte at qualities 0, 1
  and 5-8 and differed at 2-4 and 9-11 (the default is 11), so it would be
  round-trip only there. Adding it later is native-only: implement
  `BrotliEncoder`/`BrotliDecoder` in `binding.js` over two new natives.
- **Zstd** (`zstdCompress`... and the `ZSTD_*` classes) and the experimental
  **ZIP archive** API, which `lib/zlib.js` v26.8.2 carries: no pure-Rust zstd
  encoder matches libzstd, and nothing in the epic needs either. The `ZSTD_*`
  constants stay so `zlib.constants` matches Node. `ZLIB_VERNUM` is Node's.

## Shared files touched (added lines only)

`internal/errors.js` exports its `E` helper so `internal/zlib/errors.js` can
register `ERR_BUFFER_TOO_LARGE`, `ERR_TRAILING_JUNK_AFTER_STREAM_END` and
`ERR_BROTLI_INVALID_PARAM` without growing that near-limit file;
`node_host_crypto.rs` makes its `window` helper (an ArrayBuffer view's bytes
through the engine's slots) `pub(super)`.

## Verification

- `scripts/run-node-zlib-oracle.sh` (several minutes on jsse) diffs on jsse
  `--node` and Node: `matrix.js` (every input through five mode pairs x
  levels -1..9 x strategies, windowBits x memLevel, dictionaries, callbacks;
  compressed bytes only where pinned), `errors.js` (messages, codes, errnos,
  validation, `crc32`), `misc.js` (exports, `constants`, `codes`, Node-made
  golden streams) and `streams.js` (output and input chunk boundaries at
  chunk sizes 64/1000/16384 and 1/13/999/5000-byte writes, `flush()`,
  `params()`, `reset()`, `close()`, write-after-end, pipeline, multi-member
  gunzip, event order). `cross.js` then has each engine decode the 880
  streams the other compressed, whole and streamed.
- `tests/node_zlib.rs`: pinned bytes, Node-made streams, crc32, a 660-way
  round trip, callback/stream ordering, errors, a 32 MiB stream, and the
  default environment (bytecode, `--no-bytecode` and `JSSE_GC_STRESS=3`);
  unit tests in `node_host_zlib_ctx.rs` need no Node.
