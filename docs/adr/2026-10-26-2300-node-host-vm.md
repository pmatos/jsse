# Node host mode: the `vm` module

Status: accepted (#1238), epic #1214. Builds on
`2026-10-26-0854-node-host-mode.md` (floor, builtin table) and
`2026-10-26-1000-node-host-v8-errors.md` (stack capture). Test harnesses that
evaluate emitted code (#1262) and the library runners reach `vm` through it.

## Decision

1. **`require("vm")` / `node:vm` is Node's `lib/vm.js`**, trimmed: `Script`,
   `createScript`, `createContext`, `isContext`, `runInContext`,
   `runInNewContext`, `runInThisContext`, `compileFunction`, `measureMemory`
   and the frozen null-prototype `constants` (`USE_MAIN_CONTEXT_DEFAULT_LOADER`,
   `DONT_CONTEXTIFY`), with Node's argument validation and error codes. It sits
   on a pure-JS `contextify` binding (`internal/vm/contextify.js`) that is built
   from one native binding, `internal/host/vm` (`__host_vm`, taken private by
   the builtin loader like the other floor bindings). `SourceTextModule` and the
   other `vm.Module` classes are not provided.
2. **Native floor (`src/interpreter/builtins/node_host_vm.rs`).**
   - `newContext()` makes a realm (the machinery behind `$262.createRealm` and
     `ShadowRealm`) and returns its global object, minus what a V8 context does
     not have (`$262`, timers, `structuredClone`, `btoa`/`atob`, `ShadowRealm`).
     JavaScript adds the no-op V8 `console` and `Error.stackTraceLimit` /
     `Error.captureStackTrace`; `prepare(global)` gives the realm the stack
     hooks of the main one so its errors record stacks.
   - `compile(source, filename, lineOffset, columnOffset)` parses once and
     keeps the program in a table; `run(global, id)` executes it in the realm
     that owns `global` (or the caller's realm for `undefined`) with Script
     semantics: global `var`/function declarations, a global lexical scope that
     persists across runs, `let`/`const` redeclaration errors in that realm,
     the program's own strictness for that run only (the global environment's
     flag is restored), and no job-queue drain (Node does not drain either).
     `release(id)` is driven by a `FinalizationRegistry`.
   - `compileFunction(wrapper, ...)` builds the function from
     `(function (params) {\nbody\n})`, which must parse as exactly one function
     expression (so a body cannot close the wrapper), in the target realm, over
     one with-environment per context extension (later extensions innermost).
3. **Contextified objects (`internal/vm/sync.js`).** Node uses named-property
   interceptors, so the sandbox's properties are the context's globals. The
   engine's global environment now sends declarations, implicit globals and
   writes through the global object's internal methods (jsse#1346), so a Proxy
   global over the sandbox could replace this layer; until `vm` is moved to it
   the global object stays ordinary and mirrors the sandbox:
   - when a script is about to run (`enter`), every property the sandbox has,
     own or inherited from a prototype other than the main `Object.prototype`,
     becomes a **forwarding accessor** on the global: reads and writes reach
     the sandbox live, from the script, from callbacks it makes into the host
     and from functions called later. Read-only properties and names the global
     holds as non-configurable are copied as data instead and re-copied on each
     run. Properties the sandbox lost are dropped (a shadowed builtin comes
     back).
   - when it ends (`leave`), what the script left on the global (`var`,
     function declarations, implicit globals, `this.x`, `defineProperty` on
     `globalThis`, a replaced builtin) is pushed to the sandbox as
     `Object.defineProperty` would, a configurable one becomes a forwarder, a
     declared-but-unassigned `var` stays on the global only, and a name the
     script deleted is deleted from the sandbox. Declaration-shaped
     descriptors are stored on the sandbox as configurable, which is what Node
     shows.
   - `vm.createContext(vm.constants.DONT_CONTEXTIFY)` returns the new global
     object itself with no mirroring; `this`/`globalThis` inside a normal
     context is the realm's global, not the sandbox, as in Node.
4. **Errors.** A syntax error is thrown in the realm the code was compiled for
   (`new vm.Script` and `runInThisContext` use the main realm,
   `runInContext`/`runInNewContext` the context's) with Node's header above the
   stack: `file:line`, the source line and an arrow under the token the parser
   stopped at, with `lineOffset` applied. `compileFunction` reports a run-off at
   the end of its body on the body's last line. Stack frames of scripts and
   compiled functions carry `filename` (default `evalmachine.<anonymous>`, a
   `//# sourceURL=` line wins), with `lineOffset` on every line and
   `columnOffset` on the first. The top level of a running script gets a frame
   of its own (a stand-in native function on `call_stack_frames`, mapped to the
   script's source in `NodeStackState::script_frames`), so `at file:1:7`
   appears for code that is not inside a function. Names are registered weakly
   (`NodeStackState::name_pending`) and applied when a frame first mentions the
   source, so one-shot scripts that never fail cost nothing. The stack
   formatter treats any realm's global object as a top-level receiver.
5. **Options.** `filename`, `lineOffset`, `columnOffset`, `displayErrors`,
   `contextName`/`name`, `origin`, `microtaskMode`, `contextCodeGeneration`,
   `importModuleDynamically` (a function or the main-context-default constant)
   and `timeout`/`breakOnSigint` are validated like Node and the last four
   groups have no effect (below). `cachedData` is never used and reports
   `cachedDataRejected === false`; `produceCachedData`/`createCachedData()` give a
   small fixed Buffer. `measureMemory()` resolves to the `{ total }` (or
   `{ total, current, other }`) shape from `process.memoryUsage().heapUsed`.

## Known gaps

None of these is in the oracle (`scripts/vm-fixtures/{probe,errors}.js`).

- A property a script creates (`var`, function, implicit global, `this.x`) is
  visible on the sandbox only after the run that made it ends, and one created
  later by a function called from the host, or by a callback after the run
  (a timer), is visible after the next run into that context. Properties the
  sandbox already had are live. A name added to the sandbox by the host is seen
  by functions called later only after the next run.
- `Object.getOwnPropertyDescriptor(globalThis, name)` inside a context shows a
  forwarding accessor for properties that came from the sandbox, not Node's
  data descriptor. `delete globalThis.v` of a script-declared `var` leaves the
  sandbox property in place (Node removes it although the global refuses).
  `Object.keys(globalThis)` lists sandbox properties before script-declared ones.
  `Object.defineProperty(globalThis, x, { configurable: false, ... })` is
  stored on the sandbox as configurable when the descriptor is also writable
  and enumerable. A sandbox's main-realm `Object.prototype` members are not
  mirrored, so `hasOwnProperty` and friends resolve to the context's own.
- No runtime error gets the `file:line / source / ^` header above its stack
  (Node adds it to errors that leave `runIn*`; the throw position is not tracked
  in this engine), and the message text of a syntax error is the parser's, not
  V8's. Engine-made runtime errors (`null.x`) report the start of the
  enclosing call, not the property access, in their first frame, as everywhere
  under `--node`. Frames of `lib/vm.js` itself read `<anonymous>`, not
  `node:vm`.
- `timeout`, `breakOnSigint`, `microtaskMode: 'afterEvaluate'` (the context
  shares the job queue), `contextCodeGeneration` (`eval`/`Function` stay
  enabled), `cachedData` acceptance and `importModuleDynamically` callbacks
  (`import()` in a script uses the default loader) are accepted and ignored.
  A script that never returns cannot be interrupted.
- `script.sourceURL`/`sourceMapURL` come from a text scan of the source (a
  directive inside a string literal counts); a frame takes `sourceURL` only
  from a line of its own.
- Each run into a contextified object scans the realm's global and the object
  (about 0.25 ms for a default sandbox); creating a context costs about 2 ms.
- Every context is a realm, and realms are never freed: a program that creates
  thousands of contexts (a harness that evaluates each emitted file in a fresh
  one) grows by the size of one set of intrinsics per context.
- `vm.Script`'s compiled program is kept until the `Script` is collected; a
  loop that creates many scripts relies on the `FinalizationRegistry` to free it.
- `Function.prototype.toString` of a `compileFunction` result is
  `function (a, b) {\nbody\n}` as in V8; the function has the engine's usual
  sloppy-function own keys (`caller`, `arguments`).

## Verification

`scripts/run-node-vm-oracle.sh` runs the fixture matrix on Node, checks Node's
output against the pinned `scripts/vm-fixtures/expected-*.txt`, and diffs jsse
`--node` (bytecode VM and `--no-bytecode`) against it. `tests/node_vm.rs` holds
jsse to the pinned file without Node (also under `JSSE_GC_STRESS=7`) and checks
the private binding, the cleaned context globals and the default environment.
