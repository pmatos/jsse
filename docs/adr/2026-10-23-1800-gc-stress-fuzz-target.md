# `gc_stress` fuzz target: in-process GC stress with a transparency oracle

Status: accepted (#1178); builds on the `execute` target (ADR 2026-10-23-1400).

## Context

`JSSE_GC_STRESS=N` forces a collection at every Nth safepoint, alternating major
(finds missing roots) and minor (finds missing write barriers). It was only ever
applied to fixed corpora (`test262-extra/` in `ci.yml`, a nightly test262
sample). It is read once per interpreter from the environment, so a fuzz input
could not vary it, and `set_var` is process-global and `unsafe` in edition 2024.

## Decision

- `fuzz/fuzz_targets/gc_stress.rs` calls `jsse_fuzz::gc_stress::fuzz_gc_stress_bytes`.
- Input: byte 0 is a header, the rest is UTF-8 JS source (otherwise ignored, as
  in `execute`). `period = PERIODS[b & 7]` with `PERIODS = [1, 2, 3, 5, 7, 16,
  61, 251]`; bit 3 selects the tree-walker instead of the bytecode VM. The
  header mutates independently of the source, so libFuzzer keeps exploring
  periods. Rejected: deriving the period from a hash of the source, where a
  one-byte source edit reshuffles the period.
- The period is applied in-process: `jsse::run_script_gc_stressed(src, budget,
  bytecode, period)` calls `Interpreter::set_gc_stress_period`, which overrides
  whatever `JSSE_GC_STRESS` said (period 0 is an explicit "off", so an exported
  variable cannot turn the baseline run into a stressed one).
- Oracle: besides panic / abort / debug assertion (`gc_assert_root_depth`, the
  LIFO root-stack asserts) / sanitizer report, the script runs twice in the
  same mode, stress off and stress on, and the `RunSignature`s must be equal. A
  collection is unobservable in ECMAScript except through `WeakRef`,
  `FinalizationRegistry` and `WeakMap` liveness, so a difference means a live
  value was freed (a recycled arena slot shows up as a wrong-typed value or a
  spurious `TypeError`) or a write barrier was missed. A divergence panics with
  `gc stress divergence (period N, mode)`.
- Two runs per input, not a four-way bytecode x tree-walker x stress matrix:
  the mode bit picks which engine gets covered, and bytecode-vs-tree-walker is
  `execute`'s job. Four runs would halve throughput.
- Skip list reuses `execute`'s: inputs naming `agent`, `waitAsync` or `sleep` do
  not run; inputs naming `WeakRef`, `FinalizationRegistry`, `gc`, `$262`,
  `Date`, ... run (for panics) but are not compared. It is one list, exposed as
  `fuzz_input_is_runnable` / `fuzz_input_is_gc_observable`.
- Step budget scales with the period: `clamp(period * 400, 2_000, 20_000)`.
  Period 1 is a full-heap major at every safepoint, so a fixed budget would make
  low periods seconds per input. Signatures are compared exactly, including
  `BudgetExhausted`: stress does not add safepoint ticks (collection happens
  inside the tick), so a step-count difference is itself a bug signal. If that
  turns out noisy, fall back to `execution_divergence`'s skip-on-exhaustion rule.
- Seeds (`fuzz/corpus/gc_stress/`, generated by `seeds.rs`): allocation-heavy
  scripts, weighted towards native -> JS re-entry holding fresh values
  (`sort`/`map`/`reduce`/`from` callbacks, `replace`, `toJSON`, getters/setters,
  coercion, `Proxy` traps, iterator helpers), since safepoints only occur in JS
  code. Every period index and both engines have a seed, and each seed must
  reach `2 * period` stress safepoints, which proves a stressed major and a
  stressed minor both fired.
- ClusterFuzzLite: `build.sh` builds and zips the seeds for the new target and
  writes `max_len = 4096`. No workflow change; they run every target.

Measured under ASan with debug assertions (5 minutes from the seed corpus):
~400 executions/s, 119k inputs, no crash on the fixed tree.

## What it does not cover

- Collection never fires at allocation time, only at statement boundaries and
  loop back-edges, so rooting gaps that need a collection between two
  allocations inside one native call are invisible to stress by design.
- A minor-collection barrier bug surfaces only if the old -> young store
  happens before a stressed minor.
- Module inputs.
- The skip list matches identifiers in the source, so computed access like
  `globalThis["Weak" + "Ref"]` evades it; a divergence involving one is a
  harness false positive. `execute` has the same hole.

## Consequences

- The ClusterFuzzLite PR job's fixed 120 s is now split across four targets.
- Like `execute`, a latent bug can fail the blocking PR check on an unrelated PR.
  Each finding is filed as its own issue; the first two came from the seed
  corpus and a five-minute run: #1198 (`JSON.parse` reviver loses parsed values,
  deliberately kept out of the seeds until fixed) and #1199 (program completion
  unrooted while draining jobs, fixed together with this target).
